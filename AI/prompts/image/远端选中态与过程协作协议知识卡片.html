远端选中态
与过程协作协议

把“谁选中了什么”与“谁正在做什么”分开表达：选中态是用户级快照，过程协作是可清理的临时预览，正式结果仍由应用命令和事务负责。

轻量 · 可覆盖 · 不污染正式状态
状态边界远端选中态过程协作协议骨架落地规则
01

先分清：快照 ≠ 过程

selection

远端选中态

表达某位协作者当前选中的图形与连线，是用户级、可覆盖的完整快照。

  • 按用户隔离保存
  • 新快照覆盖旧快照
  • 空数组明确表示清空
interaction

过程协作

表达绘制、移动、缩放、框选中的临时状态，是一次交互会话的预览。

  • 使用 sessionId 分组
  • update 可丢帧、只留最新
  • 结束时 commit / reset 清理
canonical

正式结果

表达已经确认并进入业务模型的变化，由应用命令、领域规则和事务同步负责。

  • 不依赖远端预览
  • 包含真实受影响范围
  • 以最终提交态为准
02

远端选中态：像一张“用户名片”

视觉表达

本地选中高对比描边 + 操作手柄
远端选中用户颜色轮廓
远端框选半透明框 + 用户标记
已清空移除轮廓，不留残影
本地交互层远端用户层临时预览层正式数据层

数据只传 ID

远端渲染时按 ID 从本地正式图形和连线中取最新几何，避免完整业务对象成为长期数据源。

找不到对象时跳过该轮廓；不要写入本地正式 Store，也不要根据包围盒重新推导成员。

选中快照的最小结构

{
  "selection": {
    "shapeIds": ["shape-a", "shape-b"],
    "lineIds": ["line-7"]
  }
}

发送完整快照，不使用 sessionId；shapeIds 和 lineIds 同时为空时，删除该用户的远端选中状态。

03

过程协作：一条可回收的小纸带

start建立会话
发送初始边界 / 目标
→
update × N发送最新状态
允许丢帧
→
commit过程结束
等待正式结果
→
cleanup清理远端预览
不回写本地选择
异常路径：断线、离开、超时、工具切换、操作失败 → reset / expire → cleanup。reset 只清理未完成过程态，不表达正式业务回滚。

移动

start 携带目标图形编号和初始信息；update 只携带相对会话起点的总位移。

dx / dy

缩放

start 携带目标与手柄；update 携带约束计算后的最新边界。

bounds

框选 / 绘制

过程只展示边界或草稿，不提前创建正式图形，也不让远端推导最终成员。

preview only
04

协议骨架：同一条消息，三种语义

{
  "type": "drag",
  "data": {
    "module": "icce",
    "handleData": {
      "add / modify / delete": "正式变更",
      "selection": "用户级选中快照",
      "interaction": {
        "kind": "shape-move",
        "phase": "start | update | commit | reset",
        "sessionId": "一次过程会话"
      }
    }
  }
}
空字段省略过程几何在编码出口取整用户信息由广播层附加
05

生成与实现时的共同约束

要画出来

  • 本地与远端使用不同颜色
  • 轮廓、包围盒、用户小标签有清晰层次
  • start → update → commit / reset 方向明确
  • 用贴纸、箭头和手写注释强化学习卡片感

不要混在一起

  • 远端选中态不改本地选择
  • 过程预览不写正式图形 Store
  • 过程 session 不冒充业务 operation
  • 不要用完整业务对象填充轻量协议

一句话记忆

选中态告诉你“他看着谁”，过程态告诉你“他正在做什么”，正式态才决定“最后变成什么”。
