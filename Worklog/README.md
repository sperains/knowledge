# Worklog 工作记录规则

## 目录结构

- `Worklog/Daily/YYYY/MM/YYYY-MM-DD.md`：按天记录已完成的开发工作。
- `Worklog/Monthly/YYYY/YYYY-MM.md`：按月汇总日报中的主题、成果和经验。
- 日报和月报属于同一类工作记录，但保持不同粒度和独立文件，月报不再按月份额外分目录。

## 提交统计口径

1. 日报只统计本人提交，当前作者为 `任OvO`，邮箱为 `1012205285@qq.com`。
2. 提交作者按 Git 的作者信息过滤，不按提交者、分支名或合并来源判断归属。
3. 排除合并提交，避免同一批改动因分支合并被重复计入。
4. 无本人提交的日期不生成工作内容；其他作者的提交不得写入本人日报。

## 日报格式

1. 不记录提交时间。
2. 不记录 commit id。
3. 保持“今日工作”原有结构，不拆分工作主题和具体改动。
4. 每个提交使用带序号的小节标题。
5. 具体改动内容继续使用列表跟在对应提交下面。

## 标题习惯

- 摘要使用“今日概览”。
- 工作明细使用“今日工作”。
- 只有当天形成了可复用的架构、经验或决策时，才添加“架构与经验沉淀”。
- 只有存在重要参考文档或关联笔记时，才添加“相关资料”。

## 关系图谱规则

1. 日报涉及明确的架构主题时，优先直接链接对应设计文档和 ADR，不只链接目录索引。
2. 分层、命令、权限、移动、协作、视口、详情页和性能等主题，直接链接对应的设计文档或具体 ADR。
3. 正文中的普通文字不会形成关系，必须使用 `[[文档名]]` 或 `[[路径/文档名|显示名称]]`。
4. 链接路径以当前文件所在目录为基准；不要假设日报和月报具有相同的相对层级。

## 月报规则

- 月报以当月日报为事实来源，按工作主题合并重复内容，不按日期机械罗列。
- 只记录日报中明确出现的成果、问题、风险、经验和后续事项，不补写没有证据的完成结论。
- 不记录提交时间、提交编号、分支名和逐日流水账。
- 没有实际内容的章节删除，不保留空的“问题、风险与未完成事项”“架构与经验沉淀”或“相关资料”。
