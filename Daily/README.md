# Daily 日报规则

## 日报格式

1. 不记录提交时间。
2. 不记录 commit id。
3. 保持“今日工作”原有结构，不拆分工作主题和具体改动。
4. 每个提交使用带序号的小节标题。
5. 具体改动内容继续使用列表跟在对应提交下面。

## 标题习惯

- 摘要使用“今日概览”。
- 工作明细使用“今日工作”。
- 只有当天形成了可复用的架构、经验或决策时，才添加“架构与经验沉淀”。
- 只有存在重要参考文档或关联笔记时，才添加“相关资料”。

## 关系图谱规则

1. 日报涉及明确的架构主题时，优先直接链接对应设计文档和 ADR，不只链接目录索引。
2. 分层、命令、权限、移动、协作、视口、详情页和性能等主题，直接链接对应的设计文档或具体 ADR。
3. 正文中的普通文字不会形成关系，必须使用 `[[文档名]]` 或 `[[路径/文档名|显示名称]]`。
4. 链接路径以当前文件所在目录为基准；日报链接 ICCE 文档使用 `../ICCE/`，ICCE 文档链接 ADR 使用 `../ADR/`。
