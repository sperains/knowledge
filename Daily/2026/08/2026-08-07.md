## 今日概览

在 Workspace 搭建了 FastAPI + Pydantic v2 分层架构 REST API 项目骨架（fastapi-skeleton），并完成三轮质量加固：接入 pyright 类型检查（挖出并修复 11 个标注问题）、将各层包清理为命名空间包（删除全部死代码 `__init__.py`）。整个过程中「删除 `__init__.py` 安全」等结论均通过 build / wheel / 独立安装三连实测验证。

## 今日工作

### 1. 搭建 FastAPI 分层架构骨架

- 按 api/v1 → dependencies → services → repositories → models 单向分层组织代码，schemas 用 Pydantic v2 `from_attributes` 序列化 ORM。
- 事务边界归 service 层（repository 只做存取不 commit）；PATCH 语义用 `model_fields_set` 判断显式传入字段；业务异常 `BusinessError` 由全局处理器统一转 JSON。
- 数据库默认 SQLite + aiosqlite 零依赖可跑，生产切 PostgreSQL 只改配置。
- 工程化配套：uv 管理依赖、Makefile、Dockerfile + docker-compose、.env.example、README。

### 2. 接入 pyright 类型检查并修复 11 个标注问题

- 用户指出 `@asynccontextmanager` 函数标注 `AsyncIterator` 已弃用，暴露验证链路只覆盖 ruff + pytest、不查类型标注的问题。
- 在 `pyproject.toml` 配置 `[tool.pyright]`（standard 模式），质量门禁升级为 `make check` = ruff + pyright + pytest。
- pyright 首跑挖出 11 个真实问题并全部修复：conftest 的 async fixture 返回标注应为 `AsyncGenerator`；路由返回 ORM 但标注 Schema，改为显式 `UserRead.model_validate`；PATCH 分支内可选字段加 `assert x is not None` 收窄。

### 3. 清理 `__init__.py`，各层包退化为命名空间包

- 删除 repositories / schemas / services / models / utils / api 的 re-export 死代码 `__init__.py`，全项目仅保留 `app/api/v1/__init__.py`（router 聚合，功能性）。
- 每次删除均实测验证：`uv build` 成功、wheel 内容完整、wheel 安装到独立 venv 后 import 全部成功、`make check` 全绿。

## 架构与经验沉淀

- FastAPI 项目质量门禁必须包含 pyright（与 Pylance 同源）：ruff + pytest 覆盖不了类型标注规范，yield 函数（asynccontextmanager / async fixture）一律标注 `AsyncGenerator[T, None]`。
- Python 3.3+ 下删除 `__init__.py` 安全：hatchling 对显式 `packages=["src/app"]` 默认支持命名空间包发现，运行时、打包、独立安装三层均验证通过；`app/__init__.py` 同样非强制保留，仅功能性 `__init__.py`（路由聚合）必须存在。
- 教训：所有「必须保留」类论断必须实测（build + wheel 内容 + 独立安装 import）再下结论，不能凭对构建工具行为的假设断言。本次 `app/__init__.py` 正是凭假设断言而翻车。
