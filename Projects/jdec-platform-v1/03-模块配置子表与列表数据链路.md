# jdec-platform-v1 03 模块配置、子表与列表数据链路

> 当前结论：模块配置页面、物理表关系配置、菜单表头和业务列表属于四层不同职责。模块配置决定当前模块可使用哪些表和字段；菜单表头决定列表实际展示哪些字段；`sys_table_relation` 决定主表与关联表如何连接；动态查询引擎再根据这些配置生成执行计划。页面上的“模块子表”不等同于已经完成了主子表关联配置。

## 1. 页面没有直接展示关系类型

模块配置页面可以看到：

- 模块主表；
- 模块子表或表字段来源；
- 表字段配置；
- 模块状态配置；
- 模块树层级。

页面没有直接展示 `1:1`、`1:N`、`N:1` 等关系类型。这些关系属于配置中心的物理表关系对象 `sys_table_relation`，不是模块保存请求中的独立字段。

模块配置保存请求 `SaveModuleReq` 当前包含：

```text
module          模块基本信息，包括 primaryTable
fields          模块字段，包括 tableName、columnName
moduleStatuses  模块状态绑定
treeNodes       模块层级和排序
```

当前没有明确的：

```text
subTable
relationType
joinField
```

因此，仅从模块配置页面选中一个子表，后端能直接确认的是“某些模块字段来自另一张表”；具体如何关联，还要读取 `sys_table_relation`。

## 2. 四层配置职责

```text
模块配置
  → 定义当前模块有哪些表字段可用
  → sys_module、sys_module_field

表关系配置
  → 定义物理表之间如何连接
  → sys_table_relation

菜单表头配置
  → 定义页面列表实际选择哪些字段
  → sys_menu_header、user_menu_header

动态查询引擎
  → 根据前三层配置生成查询和装配结果
```

对应关系可以概括为：

```text
模块配置 = 可查询字段范围
菜单表头 = 实际展示字段
表关系配置 = 数据关联方式
查询引擎 = 最终执行和组装方式
```

## 3. 模块配置如何记录主表和其他表字段

### 主表

模块主表由：

```text
sys_module.primary_table
```

决定。查询计划以它作为当前模块的根物理表。

### 其他表字段

模块字段由 `sys_module_field` 记录：

```text
module_id
table_name
column_name
display_name
biz_key_order
sort_order
```

如果同一个模块的字段出现不同的 `table_name`，表示该模块字段配置覆盖了多张物理表。但这并不自动证明这些表之间存在可查询关系，仍需要在 `sys_table_relation` 中找到对应关系。

相关源码：

- `SysModule.primaryTable`：`jdec-platform-config-biz/.../entity/SysModule.java`
- `SysModuleField.tableName`：`jdec-platform-config-biz/.../entity/SysModuleField.java`
- `SaveModuleReq.fields`：`jdec-platform-config-api/.../dto/request/SaveModuleReq.java`

## 4. 物理表关系如何参与查询分支

`sys_table_relation` 记录：

```text
main_table    主表
main_field    主表关联字段
join_table    关联表
join_field    关联表字段
relation_type 1:1、1:N、N:1
```

### 主表字段

如果字段的 `tableName` 等于模块的 `primaryTable`，字段进入主表投影：

```sql
select info.id, info.company_name
from info
```

### 一对多关联表字段

查询编译器会从主表的正向关系中识别 `1:N` 关联，再判断模块字段是否来自关联表：

```text
模块主表：info
字段表名：company_contact
关联记录：info → company_contact，关系类型 1:N
```

此时会把字段分组到一对多从表，并自动生成同模块子表查询计划：

```text
当前模块
├─ 主表计划：info
└─ 同模块子表计划：company_contact
```

查询计划中的子表计划会保存：

```text
primaryTable       company_contact
parentKey          info.id
parentForeignKey   company_contact.company_id
projectedFields    company_contact 的模块字段
```

相关代码：

- [QueryPlanCompiler.java](/Users/sperains/jd/jdec-platform-v1/jdec-platform-data-biz/src/main/java/com/jdec/platform/data/biz/plan/compiler/QueryPlanCompiler.java:386)
- [QueryPlanCompiler.java](/Users/sperains/jd/jdec-platform-v1/jdec-platform-data-biz/src/main/java/com/jdec/platform/data/biz/plan/compiler/QueryPlanCompiler.java:459)

### 一对一或多对一关联表字段

`1:1` 或 `N:1` 不会按集合型子节点处理，而是生成伴随表关联：

```text
companionJoins
```

查询执行时可能表现为 `LEFT JOIN`，适合读取一对一扩展资料或关联字典信息。

相关代码：

[QueryPlanCompiler.java](/Users/sperains/jd/jdec-platform-v1/jdec-platform-data-biz/src/main/java/com/jdec/platform/data/biz/plan/compiler/QueryPlanCompiler.java:499)

## 5. “同模块子表”和“独立子模块”的区别

### 同模块子表

特点：

- 子表字段和主表字段属于同一个模块；
- 字段仍使用当前模块的 `module_id`；
- 查询计划中的子计划可能仍使用当前模块 ID；
- 结果通常按物理表名挂载，例如 `company_contact: [...]`；
- 不天然拥有独立菜单、字段权限和模块生命周期。

查询结果示意：

```json
{
  "info": {
    "company_name": "某公司",
    "company_contact": [
      {
        "contact_value": "138..."
      }
    ]
  }
}
```

装配器会把同模块 `1:N` 从表直接挂载到物理表名下：

[TreeResultAssembler.java](/Users/sperains/jd/jdec-platform-v1/jdec-platform-data-biz/src/main/java/com/jdec/platform/data/biz/plan/assembler/TreeResultAssembler.java:276)

### 独立子模块

特点：

- 子表对应一个独立的 `sys_module`；
- 通过 `sys_module.parent_id` 建立模块树关系；
- 子模块拥有自己的字段、权限、查询和保存计划；
- 可以拥有独立菜单、审批和业务操作；
- 查询结果通常以模块 ID 作为嵌套节点键。

结果示意：

```json
{
  "1001": {
    "info": {
      "company_name": "某公司"
    },
    "1006": [
      {
        "company_contact": {
          "contact_value": "138..."
        }
      }
    ]
  }
}
```

因此，页面中的“模块子表”不能直接等同于“独立子模块”。需要进一步确认前端保存的是字段表名，还是模块树中的子模块编号。

## 6. 业务列表是否受模块子表影响

如果所说的列表是业务数据列表，那么它确实会受到模块子表影响，但需要经过菜单表头这一层。

完整链路是：

```text
菜单
  → 默认菜单表头或用户个性化表头
  → 选中的模块字段编号
  → QueryReq.fields
  → QueryPlanCompiler
  → 读取主表和关联表
  → TreeResultAssembler 组装列表结果
```

数据聚合服务会先通过菜单获取表头，再提取选中的字段 ID，最后调用动态数据接口：

[DataAggregateService.java](/Users/sperains/jd/jdec-platform-v1/jdec-platform-data-biz/src/main/java/com/jdec/platform/data/biz/service/DataAggregateService.java:56)

因此：

```text
模块配置了子表字段，但菜单表头没有选中
  → 列表通常不显示子表字段

模块配置了子表字段，菜单表头选中了，且表关系存在
  → 查询引擎加载子表并返回关联数据

菜单表头选中了子表字段，但模块字段或表关系不完整
  → 可能无法正确生成查询计划或执行 SQL
```

列表显示内容的职责分工如下：

| 配置 | 决定什么 |
|---|---|
| `sys_module.primary_table` | 列表根数据来自哪张表 |
| `sys_module_field` | 模块有哪些字段可以被查询和展示 |
| `sys_table_relation` | 主表和其他表如何关联 |
| `sys_menu_header` | 页面默认展示哪些字段 |
| `user_menu_header` | 当前用户对列表字段的个性化选择 |

## 7. 保存链路的差异

查询侧对同模块 `1:N` 子表有明确的自动拆分和装配逻辑。

保存侧主要递归处理：

```text
SaveReq.children
或
数字模块 ID 对应的子模块节点
```

保存计划会根据父子模块和 `sys_table_relation` 推导外键，并递归保存子模块记录：

- [SavePlanCompiler.java](/Users/sperains/jd/jdec-platform-v1/jdec-platform-data-biz/src/main/java/com/jdec/platform/data/biz/plan/compiler/SavePlanCompiler.java:90)
- [SavePlanExecutor.java](/Users/sperains/jd/jdec-platform-v1/jdec-platform-data-biz/src/main/java/com/jdec/platform/data/biz/plan/executor/SavePlanExecutor.java:159)

当前代码中没有看到与查询侧完全对称的“同模块物理子表自动保存”分支。`SavePlanExecutor` 会过滤 `children` 和数字模块键，并把它们作为子模块递归处理；因此如果页面选择子表后要同时保存子表数据，需要继续核对前端是否把子表数据转换成独立子模块或单独保存请求。

## 8. 当前 `company` 示例

已核验的部分关系包括：

```text
info.id → basic_info.company_id       1:1
info.id → address.company_id           1:1
info.id → company_contact.company_id   1:N
info.id → member.company_id            1:N
member.id → member_contact.member_id   1:N
```

但在当前模块树中，`member`、`member_contact`、`company_contact` 等也被配置为独立模块或虚拟模块下的子模块。因此同一张物理表既可以参与模块字段关联，也可以作为独立子模块的主表，最终取决于模块配置方式和请求结构。

## 9. 当前确定结论和待核验事项

### 已确认

1. 页面不直接展示 `1:1`、`1:N`、`N:1`，关系类型来自 `sys_table_relation`。
2. 模块配置决定当前模块可使用的字段表名，菜单表头决定列表实际选择的字段。
3. 查询引擎会根据字段表名和表关系区分主表字段、伴随表字段和 `1:N` 子表字段。
4. 同模块子表和独立子模块在查询计划、返回结构和权限边界上不同。
5. 左侧模块树来自 `sys_module.parent_id`，不等同于业务列表中的子表数据。

### 待核验

1. 截图对应前端选择“模块子表”后，是否只提交 `fields[].tableName`，还是同时调用表关系或子模块接口。
2. 同模块 `1:N` 子表在真实保存接口中是否由前端转换为 `children` 或独立子模块请求。
3. 当前业务列表菜单表头是否已经包含子表字段，以及角色字段权限是否会进一步过滤这些字段。
4. 未配置 `sys_table_relation` 时，子表字段在真实接口中是被拒绝、生成错误 SQL，还是由前端禁止保存。
