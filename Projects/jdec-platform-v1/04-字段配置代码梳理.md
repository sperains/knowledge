# jdec-platform-v1 04 字段配置代码梳理

> 当前结论：字段配置是独立的系统设置菜单，主要维护项目业务库中物理表字段的公共属性；它不直接负责把字段挂到模块上。模块字段归属由 `sys_module_field` 表达，字段值与审批链的扩展关系由 `sys_field_value` 表达。

## 1. 页面职责

```text
项目 + 主体
  → 读取业务库 INFORMATION_SCHEMA.COLUMNS
  → 合并 sys_field 字段公共配置
  → 展示物理表和物理列
  → 编辑字段显示、引用、权限和组合信息
  → 保存字段扩展值及审批链关系
```

字段配置页解决“物理字段是什么、怎么展示、是否参与数据权限、是否引用其他业务数据、如何组合转换”，不直接决定“字段属于哪个业务模块”。模块归属要回到模块配置页面的 `sys_module_field`。

## 2. 页面和后端入口

Controller：

```text
jdec-platform-config-biz/src/main/java/com/jdec/platform/config/biz/controller/SysFieldController.java
```

Service：

```text
jdec-platform-config-biz/src/main/java/com/jdec/platform/config/biz/service/SysFieldService.java
```

主要接口：

| 接口 | 用途 |
|---|---|
| `GET /api/config/tables` | 查询当前项目业务库的物理表 |
| `GET /api/config/tables-with-columns` | 查询所有表及列，并合并字段配置 |
| `GET /api/config/tables/{tableName}/columns` | 查询指定表的列和字段配置 |
| `GET /api/config/tables/{tableName}/columns/settings` | 查询指定表的完整字段配置 |
| `GET /api/config/tables/{tableName}/columns/simple-settings` | 查询指定表的简版字段配置 |
| `POST /api/config/tables/{tableName}/columns/settings` | 保存或更新单个字段配置 |
| `GET /api/config/data-permission-fields` | 查询已设置为数据权限字段的字段列表 |

Controller 从 `AppContext` 获取项目编号和主体编号，再交给 `SysFieldApi` 处理。

## 3. 三类字段对象和一张扩展表

### 3.1 物理字段元数据

数据库实际列来自 `INFORMATION_SCHEMA.COLUMNS`，包括表名、列名、列类型、数据库列注释和原始排列顺序。没有 `sys_field` 配置时，页面通常使用数据库列注释或列名作为默认显示名称。

### 3.2 `sys_field`：字段公共配置

实体：`SysField`，表：`sys_field`。

| 字段 | 含义 |
|---|---|
| `project_no` | 项目编号，决定业务库范围 |
| `subject_id` | 主体编号 |
| `table_name` | 物理表名 |
| `column_name` | 物理列名 |
| `display_name` | 前端显示名称 |
| `relation_business_no` | 外部关系业务编号 |
| `relation_name` | 关系名称 |
| `data_right_flag` | 是否生成数据权限节点 |
| `encrypted` | 是否加密存储 |
| `refer` | 是否引用，页面文案需要结合前端确认 |
| `combine_info` | 组合字段来源映射和转换配置 |

`sys_field` 本身没有 `module_id`，按照“项目、主体、表、列”维护公共配置。

### 3.3 `sys_module_field`：模块字段归属

实体：`SysModuleField`，表：`sys_module_field`。

| 字段 | 含义 |
|---|---|
| `module_id` | 字段所属模块 |
| `table_name` | 字段所在物理表 |
| `column_name` | 字段所在物理列 |
| `display_name` | 模块字段展示名称 |
| `biz_key_order` | 业务唯一标识字段顺序 |
| `sort_order` | 模块内字段排序 |

模块配置页面保存字段时，操作的是 `sys_module_field`，不是 `sys_field`。

### 3.4 `sys_field_value`：字段值扩展配置

实体：`SysFieldValue`，表：`sys_field_value`。

| 字段 | 含义 |
|---|---|
| `field_id` | 关联 `sys_field.id` |
| `module_id` | 该字段值所属模块 |
| `module_name` | 模块名称冗余 |
| `field_value` | 字段特定业务值 |
| `approval_chain_type_id` | 关联审批链分类 |
| `sort_order` | 展示排序 |
| `enabled` | 是否启用 |

截图弹窗下方的“字段值关联审批链”对应这张表，而不是 `sys_field` 主表。

## 4. 页面字段映射

| 页面项 | 后端字段 | 当前理解 |
|---|---|---|
| 字段显示名称 | `sys_field.display_name` | 覆盖数据库列注释，作为页面展示名称 |
| 关系名称 | `relation_business_no`、`relation_name` | 绑定外部关系词或业务关系 |
| 字段存储是否加密 | `encrypted` | 标记字段存储是否加密 |
| 是否生成数据权限节点 | `data_right_flag` | 决定是否创建字段对应的数据权限节点 |
| 是否脱敏/是否来自其他业务数据引用 | `refer` | 后端注释为“是否引用”，页面文案和实际语义仍需确认 |
| 是否组合字段 | `combine_info` | 保存组合字段来源映射和转换方法 |
| 关联字段 | `combine_info.sourceMapping` | 组合字段的来源字段映射 |
| 转换方法 | `combine_info.transformer` | 组合字段值的转换方式 |
| 字段值关联审批链 | `sys_field_value` | 按模块、字段值和审批链分类保存扩展关系 |

## 5. 查询和保存链路

### 5.1 查询

```text
GET /api/config/tables/{tableName}/columns/settings
  → SysFieldController
  → SysFieldService.querySysFields
  → INFORMATION_SCHEMA.COLUMNS
  → sys_field
  → sys_field_value
  → sys_module_field
  → SysFieldResp
```

字段服务会读取真实列、合并 `sys_field`、查询 `sys_field_value`，再根据 `table_name` 查询 `sys_module_field`，按 `column_name` 把字段映射到使用它的模块。因此，页面没有模块选择框，不代表后端完全没有返回模块使用信息。

### 5.2 保存

```text
POST /api/config/tables/{tableName}/columns/settings
  → 读取旧字段和旧字段值
  → 新增或更新 sys_field
  → 处理 data_right_flag 变化
  → 重建 sys_field_value
  → 同步外部关系绑定
  → 记录字段审计日志
  → 返回最新字段配置
```

保存字段配置不会直接修改 `sys_module_field` 的模块归属。

## 6. 数据权限节点副作用

```text
data_right_flag = 1
  → 创建 sys_data_permission
  → code = table_name + "*" + column_name

data_right_flag 从 1 改为其他值
  → 检查数据权限节点是否被角色引用
  → 创建必要快照
  → 删除数据权限节点
  → 记录删除审计
```

因此，“是否生成数据权限节点”不是单纯的展示开关，会影响后续角色数据权限配置。

## 7. 和其他模块的关系

```text
sys_field
  ├─ 字段公共展示和物理属性
  ├─ sys_field_value
  │    └─ 模块 + 字段值 + 审批链分类
  └─ table_name + column_name
       └─ sys_module_field
            ├─ module_id
            ├─ sys_menu_header
            └─ sys_role_module_field_permission
```

```text
物理表字段
  → sys_field：字段公共属性
  → sys_module_field：模块是否使用该字段
  → sys_menu_header：页面是否展示该字段
  → sys_role_module_field_permission：角色能否申请、查看、编辑
  → QueryReq.fieldIds：进入动态查询
```

字段配置和模块配置通过表名、列名形成语义关联，不能把 `sys_field.id` 直接当作模块字段权限中的 `moduleFieldId`。

## 8. `company` 示例

可以使用 `approval_business.module_id` 作为样本：

```text
approval_business.module_id
  → 查询 sys_field：看显示名称、关系、权限节点等公共配置
  → 查询 sys_module_field：看哪些模块使用该列
  → 查询 sys_field_value：看是否有模块级字段值和审批链配置
  → 查询菜单表头：看页面是否展示
  → 查询角色字段权限：看角色是否能查看或编辑
```

## 9. 当前结论和待核验事项

### 已确认

1. 字段配置页是独立配置菜单，主实体 `sys_field` 没有 `module_id`。
2. 字段列表由业务库物理列和 `sys_field` 公共配置合并生成。
3. `sys_module_field` 负责字段与模块的实际归属。
4. `sys_field_value` 负责字段值与模块、审批链分类的扩展关系。
5. 开启字段数据权限标记会创建对应的 `sys_data_permission` 节点。
6. 字段配置保存会触发字段值处理、外部关系绑定和审计日志。

### 待核验

1. 前端是否展示后端 `SysFieldResp.modules` 返回的模块列表。
2. 页面“是否脱敏”和“是否来自其他业务数据引用”是否都映射到后端 `refer`。
3. `combine_info` 的来源映射和转换方法在业务查询、保存阶段的实际使用位置。
4. 字段数据权限节点创建后，角色数据权限条件在动态查询中的完整注入位置。
