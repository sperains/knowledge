# fastapi-skeleton 项目概览

> 当前结论：项目已经形成分层架构、异步事务边界、命名空间包和类型检查质量门禁；由于源码仓库与提交信息尚未记录，当前实现状态标记为待核验。

## 项目定位

面向 FastAPI、Pydantic v2 和 SQLAlchemy 2.0 async 的分层 REST API 项目骨架，用于提供类型安全、可测试且可部署的后端起点。

## 技术基线

- FastAPI 与 Pydantic v2，使用 `from_attributes` 序列化 ORM 对象。
- SQLAlchemy 2.0 async；默认 SQLite，生产环境计划使用 PostgreSQL 与 asyncpg。
- pydantic-settings 管理配置，uv 管理依赖。
- Ruff、pyright 和 pytest 组成质量门禁。

## 架构基线

```text
api/v1
  → dependencies
  → services
  → repositories
  → models
```

- 路由负责参数绑定和响应声明。
- 依赖层负责对象装配与请求生命周期。
- 服务层承载业务规则和事务边界。
- 仓储层只负责 SQL 存取。
- 除路由聚合入口外，层包使用命名空间包和显式完整导入路径。

## 质量门禁

当前约定使用 `make check` 统一执行 Ruff、pyright 和 pytest。只有全部通过才视为完成。
