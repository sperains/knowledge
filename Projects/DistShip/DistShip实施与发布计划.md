# DistShip 实施与发布计划

> 当前结论：可靠部署主路径已经完成并通过首个真实项目验收；发布分发链路与第二个结构不同的静态前端项目验证是当前剩余主线。

## 文档职责

本文只维护当前实施状态、下一步、验收条件和待定事项。产品定位、命令与配置协议、安全边界和模块设计见 [[DistShip开源项目设计与实施计划]]；长期技术选择见 [[ADR/ADR-001-首版采用Go单二进制并编排系统部署工具]]。

## 当前状态

截至 2026-08-12：

- Go 1.26 工程、Cobra 命令骨架和版本一 TOML 配置协议已经建立。
- `init`、`list`、`check`、`deploy`、配置校验、目标删除和版本命令已经实现。
- 预检查、本地构建、产物校验、部署锁、远端目录创建、增量上传、结果摘要和本机成功部署历史已经闭环。
- 英文与简体中文界面、终端语言检测、颜色禁用和安全目录校验已经落地。
- 单元测试、竞态测试、静态检查、依赖校验、macOS 与 Ubuntu 持续集成已经建立。
- 首个真实 IPD 测试环境已经完成只读预检查和完整部署验收，本地与远端入口文件校验值一致。

## 发布门禁

`v0.1.0` 发布前必须满足：

1. 至少两个真实静态前端项目完成迁移验证。
2. `go test ./...`、`go test -race ./...`、`go vet ./...` 和依赖校验通过。
3. macOS 与 Linux 均完成安装、初始化、检查和部署主路径验证。
4. 四个平台构建产物和校验文件由发布流水线生成。
5. README、安全政策、许可证、贡献说明、升级和卸载说明与实际命令一致。
6. 部署确认始终展示项目、环境、分支、当前提交和远端目标。
7. 任何失败链路不得追加成功部署历史，模拟模式不得构建、联网或写历史。

## 已知风险

- 用户机器上的 Git、SSH、`rsync` 和构建工具版本仍会影响行为。
- 不同系统的命令参数、路径和权限存在差异，需要真实系统验证。
- 默认增量覆盖不会删除远端旧资源，可能保留已经从本地产物移除的文件。
- 用户配置的构建命令可以执行任意操作，必须只加载可信配置。
- 本机部署历史不是服务器权威版本，也不能代表其他电脑的部署结果。

## 待定事项

- GitHub 仓库所属账号、Go 模块完整路径和 Homebrew Tap 名称。
- 首版退出码的稳定协议。
- `show`、结构化输出、安静模式和命令补全是否进入后续版本。
- macOS 签名、公证、发布产物签名和软件物料清单的首版范围。
- 运行日志与本机部署历史的保留、脱敏和损坏恢复规则。
