# ICCE 画布退出键分层取消设计

## 当前结论

退出键遵循“每次只消费一层、编辑态优先、活动交互优先于清空选中结果”的顺序。文末实施状态记录当前代码落地情况，交互表记录各层的取消语义。

## 背景

画布原有退出键主要处理活动交互和连线工具，弹窗、菜单、文本编辑器及局部拖拽各自监听键盘事件。多个监听器缺少统一优先级时，同一次按键可能同时关闭浮层、终止画布交互或改变工具状态，也难以稳定表达“先取消当前动作，再取消选中”的逐层退出语义。

本设计将退出键定义为画布界面的统一“退出当前层”操作，对齐常见白板产品的操作习惯，同时保持本地交互、协作过程态和最终选中结果之间的职责边界。

## 核心决策

### 一次按键只退出一层

退出键按照界面与交互层级由高到低处理：

1. 文本编辑器和当前可见弹窗。
2. 工具菜单、浮动工具栏菜单和其他弹出层。
3. 快速添加、拖拽创建、尺寸调整、连线控制点等局部交互。
4. 区域草稿、画布平移和当前工具行为。
5. 兜底的临时预览或连线工具状态。
6. 当前图形和连线选中结果。

任一层确认消费后立即结束分发，不继续处理下层状态。相同优先级下优先处理后注册的活动处理器；处理器可以显式拒绝消费，让事件继续向下分发。

### 编辑态优先于画布快捷键

文本编辑器在文档事件阶段完成保存或退出，并阻止事件继续进入画布快捷键。普通输入框没有对应上层处理器时，画布快捷键保持不介入，避免退出键误清理画布状态。

可见弹窗通过统一弹窗处理器或弹窗自身取消入口消费退出键。区域创建弹窗关闭时同步清理远端区域草稿；本地区域草稿仍作为下一层状态保留，再次按退出键时才取消。

### 活动交互优先于取消选中

画布存在活动交互时，退出键只取消当前动作，不同时清空已有选中结果。框选、绘制、拖拽、连线、快速添加等过程结束后，再次按退出键才清空当前图形和连线选中。

取消选中只修改最终选中状态，由既有选中状态同步链路广播空快照；不得为取消选中创建过程态消息。框选等有过程态的操作在取消时发送重置相位，清除远端临时预览。该边界遵循 [[ADR/ADR-016-选中结果与交互过程分离承载]]。

## 各交互的取消语义

| 场景 | 退出键行为 |
| --- | --- |
| 文本编辑 | 保存当前内容并退出编辑，阻止画布继续处理 |
| 弹窗 | 关闭当前可见弹窗；区域创建同步重置远端草稿 |
| 工具菜单与弹出层 | 仅关闭最上层菜单或弹出内容 |
| 框选与图形绘制 | 清除本地预览和交互会话，并重置对应协作过程态 |
| 快速添加与拖拽创建 | 取消当前候选、连接预览和拖拽创建会话 |
| 连线创建与端点重连 | 清除连接点、路径和协作预览；端点重连恢复进入重连前的工具 |
| 中键或手形工具平移 | 正常结束平移会话并完成视口收尾 |
| 尺寸调整与连线控制点拖动 | 结束当前会话并提交已实时写入的状态，不执行回滚 |
| 无活动交互但存在选中 | 清空图形和连线选中结果 |
| 无活动状态 | 不消费退出键 |

## 实现边界

- 退出键分发器只负责判断优先级和选择唯一消费者，不直接读取具体业务状态。
- 各弹窗、菜单和局部交互负责声明自身是否活动，并复用已有关闭、提交或取消入口，禁止复制另一套清理逻辑。
- 画布级取消由舞台事件编排层调用当前工具的取消能力；工具退出与主动取消可以共享清理实现，但应保留不同的选中语义。
- 过程态取消必须清理本地预览并发送协作重置；最终选中清理由选中状态快照链路负责。详细协作边界见 [[ICCE画布交互协作设计方案]]。
- 已在拖动过程中实时写入的数据，退出时按正常提交路径收尾；需要真正回滚的交互必须先具备独立快照，不得假设退出键天然代表数据回滚。
- 新增可被退出键关闭的界面状态时，应先确定所属层级，再接入统一分发器；不得恢复互不知晓的全局键盘监听器。
