# ICCE 智能对齐吸附设计方案

## 当前结论

- 对齐候选、锚点、屏幕像素阈值和冲突优先级已形成统一设计。
- 吸附结果必须进入拖拽预览和最终移动计划，不能由渲染层单独修正。
- 本文仍是接入方案，不把“设计完成”表述为所有移动入口已经完成接入。

## 一、背景

当前画布已经具备无限网格背景能力，但无限网格与 Miro 类智能对齐属于两种不同的交互能力：

- 无限网格负责提供画布空间参照。
- 智能对齐负责在图形靠近其他图形时，自动对齐边缘、中心线或轴线。

本方案不将智能对齐建立在网格绘制逻辑之上，避免视觉网格、对象移动和吸附规则相互耦合。

## 二、目标

实现类似 Miro 的智能对齐效果：

1. 单个图形移动时，可以吸附到其他图形的左边、右边、水平中心、顶部、底部和垂直中心。
2. 多选图形移动时，以整个选区的边界和中心作为对齐基准，保持选中图形之间的相对位置不变。
3. 图形接近对齐位置时显示水平或垂直辅助线。
4. 吸附阈值使用屏幕像素计算，并根据当前缩放换算为画布世界坐标。
5. 吸附结果与拖拽预览、最终移动计划使用同一套坐标结果，避免图形抖动。
6. 跨区域移动继续禁止区域扩容和推挤。

## 三、非目标

本阶段暂不实现以下能力：

- 等间距分布。
- 自动平均分布。
- 复杂的区域布局整理。
- 连接线端点吸附。
- 以无限网格线作为主要吸附对象。

无限网格仍然只负责背景绘制。后续可以将网格吸附作为没有对象对齐候选时的弱兜底能力，但不应替代对象智能对齐。

## 四、对齐模型

### 4.1 图形锚点

每个可参与对齐的图形提供以下锚点：

- 水平方向：左边、水平中心、右边。
- 垂直方向：顶部、垂直中心、底部。

单个图形移动时，使用图形自身的锚点与候选图形锚点进行比较。

多选移动时，将所有选中图形视为一个整体，只使用整体边界的六类锚点，不对内部图形分别吸附。

### 4.2 候选图形

候选图形应满足：

- 属于当前画布。
- 不是当前正在移动的图形。
- 具有有效的几何边界。
- 不包含正在移动图形的后代图形重复项。

第一阶段默认只使用普通图形作为对齐候选。区域边界暂不作为普通对齐候选，避免与区域扩容、推挤和跨区域限制产生冲突。

### 4.3 候选查询与空间索引

智能对齐不应直接遍历图形仓储中的全部图形，而应通过候选查询接口获取附近图形：

```ts
getAlignmentCandidates(bounds, threshold): Shape[]
```

查询范围为“当前移动图形整体边界向外扩展吸附阈值”后的矩形。查询结果再经过当前选区、后代图形和图形类型过滤。

候选查询分两个阶段实现：

1. 初版使用普通遍历实现候选查询接口，用于验证对齐规则和交互效果。
2. 图形数量增大或拖拽性能不足时，将接口内部替换为空间索引，智能对齐计算模块不需要调整。

空间索引建议遵循以下规则：

- 只索引静态图形的矩形边界。
- 移动预览过程中不重建索引。
- 图形提交移动、创建或删除后更新索引。
- 当前正在移动的图形及其后代不参与候选查询。
- 区域暂不作为普通对象对齐候选。

空间索引可以后续使用四叉树或矩形树实现，具体结构不作为智能对齐模块的依赖。

### 4.4 吸附阈值

吸附阈值使用屏幕像素表示，再通过当前缩放换算为世界坐标：

```text
世界坐标阈值 = 屏幕像素阈值 / 当前缩放比例
```

只有候选锚点与移动锚点的距离小于阈值时才产生吸附。水平和垂直方向分别计算，允许只吸附其中一个方向。

### 4.5 冲突处理

同一方向命中多个候选时，按以下优先级选择：

1. 距离最近。
2. 对齐类型优先于普通边缘对齐时，使用中心线对齐。
3. 距离相同时，优先选择稳定的候选顺序，避免拖拽过程中在多个图形之间来回切换。

同一方向只保留一个吸附结果，水平和垂直方向可以同时命中。

## 五、移动处理顺序

移动过程统一遵循以下顺序：

```text
原始拖拽位置
  → 计算移动图形整体边界
  → 计算对象智能对齐
  → 应用区域边界限制
  → 生成移动计划
  → 更新拖拽预览
  → 提交最终坐标
```

区域边界限制必须在智能对齐之后生效。若吸附结果会使图形移出所属区域，则以区域限制结果为准，不扩容区域，不推挤其他区域。

跨区域多选移动继续使用现有的区域边界约束，并将区域扩容开关保持为关闭状态。

## 六、模块职责

### 6.1 智能对齐计算模块

建议新增独立的纯计算模块，例如：

```text
src/views/icce/ui/canvas/selection/alignment-snap.ts
```

该模块只处理几何计算，不读取图形仓储，不修改画布节点，不负责绘制辅助线。

建议提供以下能力：

- 根据图形边界生成对齐锚点。
- 计算移动对象与候选对象的最近对齐结果。
- 返回水平和垂直吸附位移。
- 返回命中的辅助线信息。

### 6.2 拖拽会话

拖拽会话负责保存一次拖拽过程中的：

- 初始位置。
- 当前原始位置。
- 当前吸附结果。
- 当前辅助线。
- 最终移动计划。

吸附结果应在拖拽会话中统一生成，使预览和提交使用同一个结果。

### 6.3 辅助线图层

辅助线使用独立的临时图层或现有预览图层，不写入图形数据。

生命周期：

- 拖拽开始：清空旧辅助线。
- 拖拽过程中：根据当前吸附结果更新辅助线。
- 拖拽结束、取消或阻塞：清空辅助线。

## 七、与无限网格的关系

无限网格和智能对齐共享画布坐标系，但不共享渲染控制器：

```text
无限网格
  └─ 绘制背景网格

智能对齐
  ├─ 计算图形锚点
  ├─ 计算吸附位移
  └─ 提供辅助线
```

两者都使用世界坐标，并通过当前缩放进行屏幕距离换算。无限网格的显示层级不应直接决定对象对齐结果。

## 八、分阶段实施计划

### 第一阶段：梳理现有坐标链路

- 确认单图形、区域、指针拖拽和多选移动的统一入口。
- 确认当前移动计划、区域约束和拖拽预览的调用顺序。
- 确认辅助线图层的承载位置。
- 不修改现有行为。

### 第二阶段：实现纯智能对齐计算

- 新增锚点模型和候选图形模型。
- 新增候选查询接口，避免对齐计算直接遍历图形仓储。
- 实现水平、垂直方向的最近对齐计算。
- 实现缩放相关的屏幕阈值换算。
- 覆盖正负坐标、同轴对齐和多候选冲突测试。
- 初版候选查询可以使用普通遍历，不接入实际拖拽。

### 第三阶段：接入单图形移动

- 将智能对齐接入统一拖拽会话。
- 保证拖拽预览和最终计划使用同一吸附结果。
- 保留区域边界限制和权限判断。
- 验证普通图形和区域移动不发生回归。

### 第四阶段：接入多选移动

- 使用多选整体边界参与对齐。
- 保持选中图形之间的相对位置。
- 保持跨区域移动的边界限制。
- 验证不会触发区域扩容、推挤或图形抖动。

### 第五阶段：接入辅助线

- 增加水平、垂直辅助线显示。
- 处理拖拽结束、取消和阻塞时的清理。
- 控制辅助线更新频率，避免高频拖拽造成额外渲染。

### 第六阶段：评估网格兜底和扩展吸附

- 评估无对象候选时是否启用网格吸附。
- 根据图形数量和拖拽性能评估是否将候选查询替换为空间索引。
- 后续再考虑区域边界、等间距和连接线相关吸附。

## 九、验收标准

- 图形靠近其他图形边缘或中心线时能够稳定吸附。
- 远离候选图形时不会产生强制位移。
- 缩放画布后，吸附的屏幕触发距离保持基本一致。
- 单选和多选的预览位置与提交位置一致。
- 跨区域移动不会触发区域扩容和推挤。
- 图形不会因吸附移出所属区域。
- 辅助线只在有效吸附时显示，并在拖拽结束后清除。
- 无限网格显示逻辑不依赖智能对齐模块。
