# ICCE 智能对齐吸附设计方案

## 1. 设计结论与实施状态

本方案通过可选的吸附插件，为图形拖动提供边缘与中心对齐。插件根据原始累计位移提出吸附位置，现有移动计划负责业务约束、几何规范化、预览和最终提交。

本文为统一实施设计，状态为待实施；接口定义是实施契约，不代表已有 API。源码静态核对基线为 `jd_ipd@7c5a6c005`。吸附功能尚未实现，功能测试、性能测试和浏览器验收尚未执行。

核心约束：

- 未安装插件时保持原有移动行为。
- 插件不直接修改图形、操作 Konva 节点、创建撤销记录或发送协作消息。
- 原始输入、吸附提议和最终有效位移分开保存，预览与提交使用同一份有效结果。
- 领域几何和区域业务规则继续由现有模型与移动服务提供。
- 插件会话及辅助线状态属于当前画布实例，不使用新增的模块级可变状态。

相关设计：[[ICCE画布Plan-Commit变更架构]]、[[ICCE画布交互协作设计方案]]、[[ADR/ADR-003-几何与包含关系下沉领域层]]。

## 2. 功能范围

| 场景    | 行为                                   |
| ----- | ------------------------------------ |
| 单图形拖动 | 左、中、右与上、中、下锚点对齐                      |
| 多选拖动  | 按移动主体的整体包围盒吸附，共享一个位移，保持相对位置          |
| 区域拖动  | 使用区域外框作为移动主体边界，排除随区域移动的后代            |
| 吸附参考  | 第一版使用可见普通图形；区域容器、连线、控制点不作为静态参考       |
| 吸附阈值  | 默认屏幕 6px 进入、10px 脱离，可配置；脱离阈值不得小于进入阈值 |
| 辅助线   | 只展示最终计划中精确成立的对齐关系                    |
| 启停    | 安装后默认启用，可关闭，也可由宿主输入状态临时绕过            |
| 结束与取消 | 清除辅助线、候选锁定和会话资源                      |

6px、10px 是第一版默认值，不是行业标准，需通过浏览器验收调整。临时绕过通过布尔输入提供，插件不绑定键盘事件；具体快捷键由宿主结合现有键位选择。

网格吸附、等间距、缩放吸附不属于第一版。连线端点吸附保持独立。背景网格显示与对象吸附互不控制。第一版仅提供一个可选吸附依赖，不建设通用插件注册、排序或热卸载平台。

## 3. 架构与接入位置

```text
指针位置 → 原始累计位移 → 可选吸附会话 → 吸附提议
                                           ↓
领域移动计划与几何规范化 → 有效位移和计划 → 图形预览／协作消息
                                           ↓
                                      松手提交一次
有效计划 + 仍有效的吸附命中 → 本地辅助线
```

| 位置（相对源码仓库根目录） | 职责 |
|---|---|
| `src/views/icce/ui/canvas/selection/shape-drag-interaction.ts` | 装配实例依赖，沿用单图形、多选、区域拖拽入口及提交链路 |
| `src/views/icce/ui/canvas/selection/move-session.ts` | 计算原始位移、调用吸附、校验计划、维护最后有效结果和生命周期 |
| `src/views/icce/ui/canvas/selection/geometry-preview.ts` | 应用最终计划的临时几何覆盖 |
| `src/views/icce/ui/canvas/selection/SelectionLayer.vue` | 渲染不参与命中的辅助线组件 |
| `src/views/icce/ui/viewport/viewport-metrics.ts` | 复用屏幕与画布尺寸换算 |

纯吸附计算只处理普通几何值。候选查询适配器读取领域查询和视口信息，会话负责协调；组件不复制图形边界、父子关系或区域规则。

当前拖拽入口有模块级会话变量。实施时需将本功能涉及的会话依赖按画布实例传递，并覆盖创建、取消、销毁路径；不能仅将插件局部化就宣称整个拖拽链路已实现实例隔离。不扩大到无关模块重构。

## 4. 可插拔契约

下列类型描述所需数据与生命周期；`Point`、`RectBounds` 应复用现有几何类型。

```ts
type SnapAxis = 'x' | 'y';
type SnapAnchor = 'start' | 'center' | 'end';

interface SnapCandidate {
  id: string;
  bounds: RectBounds;
}

interface SnapMatch {
  axis: SnapAxis;
  movingAnchor: SnapAnchor;
  targetId: string;
  targetAnchor: SnapAnchor;
  targetCoordinate: number;
}

interface SnapResult {
  delta: Point;
  matches: readonly SnapMatch[];
}

interface MoveSnapPlugin {
  createSession(context: {
    initialBounds: RectBounds;
  }): MoveSnapSession;
}

interface MoveSnapSession {
  resolve(input: {
    rawDelta: Point;
    scale: number;
    bypass: boolean;
    candidates: readonly SnapCandidate[];
    candidatesRevision: number;
  }): SnapResult;

  // 仅保留最终计划中仍成立的命中，用于下一帧的稳定吸附。
  accept(matches: readonly SnapMatch[]): void;
  dispose(): void;
}
```

候选由会话外的查询适配器过滤后传入，插件不读取仓储。候选集合或边界变化时递增 `candidatesRevision`；插件校验已锁定目标的身份、锚点和坐标，移除失效锁定。修订号是本地查询状态，不是协作协议字段。

`resolve` 输出提议，`accept` 反馈经实际计划校验后的命中。失败、关闭、绕过或候选失效时允许传入空命中，不保留幽灵参考线。`dispose` 必须可重复调用。

装配示意：

```ts
const snap = createAlignmentSnapPlugin({
  thresholdPx: 6,
  releaseThresholdPx: 10,
});
createCanvasMoveSessionCoordinator({ snap });

// 不装配时不建立吸附会话，也不查询吸附候选。
createCanvasMoveSessionCoordinator();
```

启停状态由当前画布持有。关闭时立即清空辅助线和锁定，下一次位置规划使用原始位移；松手刷新也必须读取最新启停状态。画布卸载、文档切换、拖拽取消与正常结束均释放吸附会话。

## 5. 候选范围与刷新

候选查询第一版采用当前视口范围，不使用“移动包围盒仅外扩阈值”的局部矩形作为唯一范围，避免漏掉同轴但距离较远的参考图形。

查询规则：

1. 对象属于当前画布，具有有效领域几何边界，且实际可见；边界与当前视口相交。
2. 单主体或同父级多选，参考对象限制为同一直接容器内的普通图形。跨容器多选按各移动根对象直接容器的并集查询。
3. 使用现有父子查询规则，不把包含区域字段与通用父子字段混用。
4. 排除所有共同移动对象、随动后代和当前会话已确认会被扩容或推挤的参考对象。锁定但可见的普通图形可以作为参考。
5. 区域容器本身不作为第一版参考目标，但允许作为移动主体。

查询适配器在拖拽开始时建立候选快照。图形创建、删除、几何或可见性变化，以及视口变化时刷新；普通指针移动不重建全量候选。初版可遍历查询，再缓存过滤结果。只有性能数据证明必要时才替换为空间索引，参考 [[ICCE空间索引与画布裁剪设计方案]]。

当前计划若发现某个参考对象被扩容或推挤，则本次拖拽内将其排除，解除对应命中。用剔除后的候选最多重算一次；若仍出现无效参考，当前帧退回原始位移规划，不循环求解。

## 6. 几何计算与稳定性

```text
原始累计位移 = 当前指针位置 − 起始指针位置
待吸附包围盒 = 起始包围盒 + 原始累计位移
提议位移 = 原始累计位移 + 吸附修正量
画布阈值 = 屏幕像素阈值 / 当前有效缩放比例
```

每帧从起始快照计算，不在上一帧吸附结果上累加。统一使用世界坐标，复用有效缩放和坐标转换规则。

X 轴比较左、中、右，Y 轴比较上、中、下。两个轴独立处理，每轴最多保留一个命中。排序规则为：

1. 已接受命中仍有效且原始位置距其不超过脱离阈值时，继续保持。
2. 否则在进入阈值内选择修正距离最小的候选。
3. 距离相同按目标标识、移动锚点、目标锚点固定排序；锚点顺序固定为起点、中心、终点，不额外加入中心优先权重。

几何边界来自领域模型，不计入阴影、选择框和控制点。多选使用移动主体的联合边界，不分别调整内部图形；区域使用其外框，子图形随动由移动服务负责。

### 几何规范化

遵循 [[ADR/ADR-003-几何与包含关系下沉领域层]]：中间计算允许浮点，持久几何与协作编码复用既有整数规范化，插件不实现私有取整函数。

移动计划规范化后，重新计算实际边界并验证命中。奇数宽度等情况可能导致理想中心对齐需要半单位位移；保留领域规则允许的最近位置，不改变尺寸或破坏多选相对位置来强行对齐。

辅助线仅在实际锚点重合时显示，比较只使用浮点计算误差容限，不将屏幕吸附阈值当作“已对齐”容差。由整数规范化产生的非零残差不显示精确对齐线，并清除该锁定。验收需覆盖半单位中心与不同缩放。

## 7. 移动会话与约束

会话分别保存原始累计位移、吸附提议、最后有效位移及其计划，不以修正后的指针位置覆盖原始输入。

逐帧处理顺序：

1. 获取最新原始位置、启停状态和候选快照。
2. 调用吸附会话得到位移提议。
3. 交给现有 `planCanvasMove`，沿用权限、区域边界、扩容与推挤参数。
4. 参考对象被本次计划改变时，按候选失效规则处理。
5. 吸附提议被阻塞时，尝试原始位移；仍被阻塞则保留最后有效计划，清除本帧吸附命中。
6. 从最终生效计划校验命中，调用 `accept`，更新辅助线与预览。
7. 协作过程消息使用最终有效位移及其区域副作用，不能使用原始指针差值替代。

只有最终选中的有效计划才能更新跨帧保留的区域副作用；探测或被丢弃的计划不得污染后续规划状态。

吸附不决定能否跨区域、是否扩容或推挤。移动入口原来允许或禁止的行为继续由现有移动规则决定，吸附不得另建一套区域约束。

## 8. 松手提交与协作变化

松手时取消待执行动画帧，同步处理尚未规划的最后输入，使用最新启停状态。没有新输入时复用最后有效结果，不能因为刷新候选而突然重新吸附到另一位置。

若远端更新已改变规划输入，沿用现有最新快照重规划语义：保留用户已看到的根目标绝对位置，重新计算区域和连线副作用。已失效参考只解除命中，不在提交阶段追随远端对象移动。最终计划被阻塞时不提交，并清理本次会话。

整个拖拽最多产生一次有效移动提交；无变化或取消不产生移动提交。历史、撤销和协作发布继续由既有应用命令负责。协作过程编码遵循既有整数规范化，因此允许协议规定的量化差异，但不得发送未经吸附的原始位移。

## 9. 辅助线表现与生命周期

辅助线由最终有效命中与实际图形边界生成，沿命中坐标连接移动主体与参考对象的边界范围，并裁剪到视口。线宽和端部留白以屏幕像素保持稳定。

第一版使用现有选择层中的独立组件，设置不参与命中，不新增持久图形或额外 Konva 图层。辅助线不进入文档、撤销历史、保存快照或协作消息。

开始时清理残留；逐帧随实际计划更新；失效、阻塞、绕过、关闭、取消、结束、切换文档和卸载时清空。辅助线与图形预览在同一次规划结果中更新，避免显示上一帧的参考关系。

## 10. 实施步骤与验收

| 步骤 | 工作 | 验收 |
|---|---|---|
| 1 | 纯几何、候选模型、稳定排序和阈值 | 边缘与中心、正负坐标、同距候选、进入脱离、缩放换算正确 |
| 2 | 候选适配与会话依赖装配 | 未装插件不查询候选且行为不变；层级、视口、随动对象过滤正确 |
| 3 | 移动计划、有效位移及反馈接入 | 预览、协作和提交使用同一有效结果；丢弃计划无区域副作用污染 |
| 4 | 辅助线、启停和释放 | 只显示实际对齐；取消、关闭和卸载无残留；实例互不干扰 |
| 5 | 浏览器与性能验收 | 单选、多选、区域及远端变化场景通过；记录实际规模与拖动耗时 |

自动验证使用 Vitest，相关测试和测试文档在源码项目 `src/views/icce/tests` 下按模块组织。必须覆盖：

- 同轴但相距较远的视口内候选不会漏选，隐藏对象和非参考类型不参与。
- 半单位中心经过领域规范化后不显示虚假精确对齐线。
- 吸附阻塞、原始位移阻塞、参考对象被推挤时没有抖动或无限重试。
- 最后一次指针更新尚未绘制就松手时，提交仍使用正确位置。
- 远端删除或移动参考对象后，锁定解除，松手不会追随其跳动。
- 插件未安装、运行中启停、取消和多画布场景保持既有移动契约。
- 正常拖拽最多一次提交，取消和无变化零提交，撤销恢复正确。

性能验收先记录现有移动基线和接入后耗时，再判断是否需要候选索引；不预先承诺未测量的节点规模。文档整理不代表上述功能验收已通过。
