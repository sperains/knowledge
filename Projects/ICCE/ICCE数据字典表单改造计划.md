# ICCE 数据字典表单改造计划

## 状态与依据

本计划依据 2026-10-21 会话中用户提供的数据字典列表、上传数据、添加数据三张设计稿，以及用户于 2026-10-21、2026-10-22 对业务规则的确认整理。源码基线为 `jd-ipd` 仓库上述提交；代码结论来自静态检查，未进行接口联调。

当前仅完成分析和规划归档，以下改造均未实施。已确认业务规则、设计稿要求、实施建议和接口待定事项分别记录；本计划不代表相关接口或功能已经具备。

## 已确认的业务规则

1. 选择位置ID后，带出该位置对应的九鼎设备名称和产线名称；两项在表单中只读展示。
2. 拉取人是当前模拟人。现有身份来源是 `auth.mock_id`，头像、姓名、工号从该模拟人的资料读取；不得改用实际登录人或其他人员补齐。展示与保存的具体字段结构需对齐接口。
3. 列表操作区双框图标表示复制功能。设计稿鼠标只是普通鼠标光标，不代表列表拖拽，也不能据此推断操作仅悬停时显示。
4. 列配置由后台接口返回。表单、操作行为和专用单元格展示可以先推进，完整列顺序、宽度、排序和筛选待后台最新配置联调。
5. 点击提交时，前端直接把选择的文件发送给后台，文件解析、数据处理由后台完成；前端不增加“先解析预览、再确认导入”的两阶段流程。
6. 允许多次上传，前端暂不处理数据重复，后台负责去重。这里不额外推导为必须支持同时选择多个文件。
7. 复制时，前端调用后台提供的复制接口，成功后刷新列表即可；前端不打开添加表单、不自行复制字段或生成新数据ID。
8. 数据编码、位置编码及相关下拉选项由后台提供接口，暂时无需关联其他字段；该规则不取消已确认的位置ID带出设备名称、产线名称。
9. 新增数据ID在保存成功后由后台生成。新建表单保持该字段为空且只读，不预申请、不在前端拼号；编辑已有数据时展示接口实际返回的ID。
10. 遵循源码仓库的数据规则：不同业务字段独立绑定，缺失字段保留空字符串或空值，不通过其他字段冒充。

### 控件与数据来源

| 项目 | 规划行为 | 确定性 |
| --- | --- | --- |
| 数据ID | 新建时为空且只读，保存成功后由后台生成；编辑展示实际ID | 用户已确认生成时机 |
| 位置ID | 下拉选择；选定后写入对应九鼎设备名称、产线名称 | 用户已确认 |
| 九鼎设备名称、产线名称 | 只读；清空或切换位置后清理对应旧值，接口缺项保留空值 | 来源已确认；清理为实施建议 |
| 数据来源 | 只读，使用接口真实来源；不因设计稿示例为“九鼎”而硬编码 | 只读来自设计稿；初始化来源待定 |
| 读写权限 | 单选：只读、只写、读写；提交枚举与接口核对 | 控件来自设计稿；枚举契约待定 |
| 数据编码、位置编码 | 带搜索入口的选择控件；后台提供选项接口，暂不联动其他字段 | 用户已确认；接口路径及值结构待提供 |
| 数据分类、数据类型 | 独立选择字段，接入后台提供的相关选项接口，暂不联动其他字段 | 控件来自设计稿；选项接口契约待提供 |
| 拉取人 | 只读展示当前模拟人的头像、姓名和工号 | 用户已确认 |
| 其余字段 | 按设计稿录入并应用对应必填校验 | 来自设计稿 |

位置选择目前仅写入设备名称，需要补齐产线名称联动；位置ID当前非必填，需要与设计稿一致。拉取人的显示来源已确定为模拟人，提交载荷仍需保证与显示身份一致。

### 字段绑定修正

以下对应键取自当前初始模型，仅作为接口核对基线，不视为最新服务端字段的最终约定。

| 业务字段 | 当前字段配置问题 | 初始模型中的独立键 |
| --- | --- | --- |
| 数据来源 | 使用 `data_source` | `data_origin` |
| 读写权限 | 使用 `data_read_write_permission` | `data_read_write` |
| 数据池ID | 使用 `data_pool_id` | `data_pool` |
| 客户设备／客户数据／九鼎数据名称编号 | 三项共用 `data_device_name_no` | `data_device_name_no`、`data_name_no`、`jiuding_data_name_no` |
| 九鼎数据位号、数据位码 | 使用 `data_device_bit_no`、`data_bit_no` | `data_jiuding_bit_no`、`data_bit_code` |
| 客户数据描述、转换后的数据描述 | 两项共用 `data_des` | `data_des`、`data_des_update` |
| 无线模块ID、名称编号 | 使用 `data_module_id`、`data_module_name_no` | `data_wireless_module_id`、`data_wireless_module_name_no` |
| 数据编码、位置编码 | 两项共用 `data_encode` | `data_number_code`、`data_position_code` |
| 数据分类、上传频率 | 使用 `data_class`、`data_upload_freq` | `data_classify`、`data_frequency` |
| 量程最大值、最小值 | 使用 `data_range_max`、`data_range_min` | `data_max_value`、`data_min_value` |
| 显示格式、初始值 | 使用 `data_format`、`data_initial` | `data_value_format`、`data_value_init` |
| 九鼎数据单位、客户数据单位 | 两项共用 `data_unit` | `data_jiuding_unit`、`data_customer_unit` |
| 换算比例k、偏移量b | 使用 `data_k`、`data_b` | `data_convert_k`、`data_offset_b` |

初始值、字段配置、详情回填和提交序列化应保持同一契约。当前回填只接收初始模型字段，提交则直接复制表单，字段命名冲突会导致空回显、串写或混合载荷，需要一起修正。

### 保存与弹窗行为

- 新增和编辑打开时正确初始化；关闭后再次打开不残留上一记录的值、校验错误或异步结果。
- 保存前执行字段校验，提交期间防止重复请求；失败时保留输入并反馈错误，成功后关闭并刷新列表。新增数据ID由后台在保存成功后生成，前端通过保存响应或刷新列表获取。
- 字段配置被详情弹窗共用，调整时同步核对详情展示，不把添加表单的可编辑性直接套到详情弹窗。
- 保持四列布局、底部保存及关闭窗口；窄屏和纵向滚动通过实际页面核验，不直接把设计稿图片尺寸作为固定运行宽度。

## 上传数据表单

### 界面规划

按设计稿保留结果提示、模板下载和文件区域；底部为提交与关闭窗口。

- 初始状态展示拖拽或点击选择文件入口，不自动向后台提交，不展示虚构的成功结果。
- 选择文件后展示 Excel 图标、当前文件名和重新选择入口；点击提交时直接把当前文件发送给后台。采用文件请求还是 `FormData`、附带哪些上下文参数，按接口契约确定。
- 选择文件不等于数据处理成功。只有后台处理成功后才显示成功提示和真实数量；设计稿“成功上传234条数据”为示例，不硬编码，也不在前端解析文件计数。
- 允许多次上传，前端不做重复数据检测、不添加重复上传拦截；后台负责数据去重。单次请求期间的按钮加载仅用于防止重复点击，不限制后续再次上传。
- 成功后刷新列表。为展示设计稿结果并便于再次上传，建议保留弹窗，通过重新选择文件继续提交，关闭窗口由用户操作。
- 模板使用字典导入约定的下载地址或接口，不直接假定现有“数据管理模板.xlsx”适用。
- 文件格式、大小限制按接口约束确定；当前组件接收 `.xls`、`.xlsx`，具体支持范围待核对。多次上传不自动等同于批量多文件上传。

### 状态与提交规则

用户于 2026-10-22 确认采用“选择文件 → 提交时发送文件 → 后台处理并去重 → 展示结果、刷新列表”的流程。前端不增加解析预览接口或二次导入确认。

| 状态 | 行为 |
| --- | --- |
| 未选择文件 | 允许选择或拖入文件，提交不可用 |
| 已选择文件 | 显示文件名，允许重新选择和提交；不展示导入成功提示 |
| 提交／后台处理中 | 当前文件直接发送后台，展示加载状态，防止单次请求重复点击 |
| 提交失败 | 展示后台错误，保留文件供重试或重新选择 |
| 提交成功 | 显示后台真实处理结果、刷新列表；允许再次上传 |

重新选择文件时更新待提交文件并清理旧成功提示，提交时始终使用当前文件；前端不解析数据、不进行去重。具体请求、返回结构及后台同步／异步处理方式按实际接口接入。若后台异步处理，接收到文件的响应不能提前当作数据处理完成。

### 当前代码差异

- `Upload.vue` 调用数据管理模块的 `bus/data/upload`、删除申请接口及 `data_apply` 通知，并从路由取申请ID；尚不能确认适用于 ICCE 字典导入。
- `UploadDataDialog.vue` 的提交仍复制单条数据字典表单并调用字典保存接口，未体现提交文件的请求载荷。
- 成功条数为固定文本，已上传文件有重复展示，重新上传后的界面不符合设计稿。

应按实际字典导入契约调整本功能组件，不连带修改其他业务模块的上传流程，也不直接删除数据申请代替移除待导入文件。

## 列表、复制与画布联动

- 修复 `DataDictListDialog.vue` 未从列表会话解构 `tableRef` 的断点，接通新增、编辑、导入和删除后的刷新。
- 列配置继续读取列表接口 `column_data`，通过专用插槽补齐读写权限标签、人员信息及复制／编辑／删除图标。
- 复制直接调用后台提供的复制接口，成功后刷新列表；具体字段复制和新记录生成由后台处理。前端不打开新增／编辑表单，不组装复制字段，也不自行生成数据ID。
- 现有拖拽是代码已有能力，是否保留或调整不由设计稿普通鼠标光标推断。拖拽名称应使用明确字段，不能从多个不同名称字段拼凑兜底。
- 编辑后的画布标签更新仍读取当前初始模型没有的 `data_name`，需要明确标签名称来源；删除通知缺失 `data_id` 时不能用记录 `id` 冒充。

## 后台接口待对接清单

业务规则已确认，以下属于技术契约待提供或核对事项，不再把已确认的业务行为列为待决策。

1. 模板下载地址、提交文件接口、文件字段及 ICCE／PFD 上下文参数、错误和结果数量结构；若后台异步处理，提供结果通知或查询方式。
2. 后台复制接口的路径、源记录标识、响应及失败信息。前端成功后刷新，复制字段与去重实现由后台负责。
3. 数据编码、位置编码、数据分类、数据类型的选项接口、显示键、值键及提交结构；暂不添加字段联动。
4. 保存响应或刷新列表如何返回生成的数据ID，以及其余业务字段的最终提交契约；不再需要新增前预生成ID的接口。
5. 数据来源初始化方式、位置接口中设备名称与产线名称的确切键名，以及模拟人提交字段。
6. 拖拽和画布标签的明确名称来源、最新列表列配置、人员数据结构，以及操作图标显示条件。
