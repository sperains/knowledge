## 一、重构目标

围绕 `src/views/icce/icce-detail.vue` 建立清晰的页面编排边界，使页面组件主要负责：

1. 页面状态编排
2. 路由变化响应
3. 标签和权限决策
4. 画布区域布局
5. 页面级生命周期管理

详情请求、视口初始化、画布会话和协作生命周期逐步下沉到独立的状态模块或组合式函数中，降低页面组件内部的副作用耦合。

## 二、当前主要问题

1. 页面组件同时承担详情请求、默认标签计算、画布加载、视口恢复、事件总线、协作会话和弹窗编排等多项职责。
2. 页面数据会话和画布会话共用监听逻辑，项目切换、标签切换和图类型切换容易互相触发。
3. `refreshALL` 同时负责请求、状态重置、竞态保护和实时消息订阅，调用入口较多，存在重复请求风险。
4. 页面就绪状态通过多个响应式字段间接推断，容易在初始空数据阶段提前放行。
5. 全局加载状态与详情页局部状态存在耦合，可能产生重复加载提示。
6. 视口初始化状态散落在页面组件中，难以单独验证和复用。
7. 模板中存在较多数字标签判断和多层条件分支，页面结构可读性较差。

## 当前落地状态

1. 第一至第四阶段已完成，第五阶段的页面级生命周期和协作切换已完成，仍保留少量事件边界验证。
2. 模板结构拆分暂缓，避免在页面状态稳定前扩大改动范围。
3. 弹窗的显示状态和业务上下文已通过 `useDialogSession` 统一管理，已覆盖区域、数据字典和模板弹窗。
4. 树抽屉状态已从 Store 移至详情页会话，并通过依赖注入共享；详情 Store 不再承载画布界面状态。
5. 画布舞台和视口运行时已提供统一的类型化注入访问函数，减少组件内的类型断言。

## 三、分阶段实施计划

### 第一阶段：建立页面状态模型

目标：明确页面当前阶段，减少通过字段存在性推断状态的逻辑。

调整内容：

1. 定义页面状态：空闲、加载中、就绪、失败。
2. 统一派生状态：业务编号、创建模式、当前标签、实际画布类型、页面就绪状态和内容权限。
3. 移除通过顶部详情空对象字段判断加载完成的逻辑。
4. 全局加载状态只负责全局遮罩，不参与详情页业务状态判断。

验收标准：

1. 加载、无权限、正常内容和异常状态分支清晰。
2. 同一区域不会被多个加载状态同时控制。
3. 默认标签不会在权限或顶部流程数据返回前提前渲染。

### 第二阶段：拆分页面数据会话和画布会话

目标：避免路由变化和标签变化互相触发重复请求。

页面数据会话负责：

1. 监听业务编号和变更模式。
2. 加载详情、互动权限和顶部详情。
3. 等待页面基础数据完成。
4. 计算默认标签。

画布会话负责：

1. 监听实际画布类型。
2. 初始化视口配置。
3. 管理画布重载标记。
4. 处理逻辑图复用流程图左侧画布的场景。

验收标准：

1. 页面基础数据请求只执行一次。
2. 标签切换不会重复请求详情接口。
3. 流程图切换到逻辑图时不重复加载左侧流程图。
4. 项目切换时旧请求不会覆盖新项目数据。

### 第三阶段：收敛详情数据加载入口

目标：建立唯一的详情数据加载入口，降低组件之间的隐式调用。

调整内容：

1. 将详情、权限、顶部详情的并行请求统一封装。
2. 提取详情状态重置方法。
3. 统一接口响应写入逻辑。
4. 保留请求版本控制，丢弃过期回包。
5. 移除业务层直接修改全局加载状态的逻辑。
6. 明确路由刷新、顶部操作刷新和提交成功后的刷新边界。

验收标准：

1. 新建提交后不会重复请求详情、权限和顶部详情。
2. 顶部操作刷新和路由刷新职责明确。
3. 旧请求回包不会污染当前页面。
4. 实时消息订阅在成功、失败、切换和卸载场景都能清理。

### 第四阶段：抽离视口初始化逻辑

建议新增：

```text
src/views/icce/ui/viewport/useViewportInitialization.ts
src/views/icce/infrastructure/adapters/viewport-layout-adapter.ts
```

负责内容：

1. `useViewportInitialization` 负责当前视口初始化会话、画布加载完成后的视口恢复、首次自适应缩放和旧会话失效判断。
2. `viewport-layout-adapter` 负责布局接口编排、配置与记录解析，以及保存参数组装。
3. `src/api/custom/index.ts` 只负责原始接口请求，不新增重复的接口包装层。
4. `globalData` 和 `viewportController` 只在视口组合式函数中用于应用运行时状态。

页面组件只保留视口组合式函数的调用和必要参数传递。

验收标准：

1. 页面组件不再直接维护视口初始化会话变量。
2. 视口恢复逻辑可以独立测试。
3. 切换图类型时位置和缩放配置仍能正确恢复。

### 第五阶段：整理事件和协作生命周期（部分完成）

目标：统一事件订阅、取消和协作会话管理。

调整内容：

1. 统一管理画布加载、视口变化、工具栏和全屏事件。
2. 保留画布加载事件在初始化阶段订阅，避免丢失快速完成事件。
3. 页面卸载时取消事件订阅、节流函数和协作会话。
4. 集中处理协作会话的加入、离开和路由变化。

已完成：

1. 视口事件由 `useViewportInitialization` 管理。
2. 页面级事件、窗口尺寸监听和协作会话由 `useIccePageLifecycle` 管理。
3. 页面组件仅提供业务回调，不再直接维护页面级挂载和卸载清理。
4. 路由业务编号变化时，先离开旧协作会话，再加入新协作会话。

验收标准：

1. 页面反复进入和退出不会重复触发事件。
2. 画布加载完成事件不会丢失。
3. 协作鼠标和实时连接不会残留。
4. 页面卸载后不会继续保存视口数据。

### 第六阶段：简化模板结构（暂缓）

该阶段暂不执行。当前模板拆分收益有限，且会扩大画布、抽屉和弹窗的联动风险。后续只有在页面功能继续增长、模板维护成本明显上升时再评估拆分以下组件：

```text
IcceDetailContent.vue
IcceCanvasLayout.vue
IcceRightCanvas.vue
```

职责建议：

1. `icce-detail.vue`：页面状态、路由和权限编排。
2. `IcceDetailContent.vue`：创建、加载、无权限和正常内容分支。
3. `IcceCanvasLayout.vue`：左右分栏和左侧画布。
4. `IcceRightCanvas.vue`：流程图右侧画布和逻辑图画布切换。

组件拆分应建立在状态流稳定之后，避免把未整理的复杂逻辑分散到多个文件。

### 第七阶段：整理状态模块（按职责收敛完成）

本阶段不拆分 Store 文件，改为先移除不必要的画布界面状态：

1. `icceStore.ts` 只保留详情、权限、顶部信息和标签等必要业务状态。
2. 弹窗会话由功能模块内部管理，不再将表单和详情弹窗状态放入 Store。
3. 树抽屉由详情页级会话管理，通过依赖注入供工具栏和抽屉组件共享。
4. 视口布局接口编排与数据转换继续由视口适配器和组合式函数负责。
5. 画布搜索、未绑定节点等单组件状态已下沉到 `CanvasTop.vue`。
6. 分栏尺寸同步已收敛到 `useIcceSplitLayout`，标签、权限和内容可见性已收敛到 `useIcceDetailAccess`。
7. 新建权限跳转改为监听菜单是否就绪和权限结果，不再深度监听整棵菜单树。

### 第八阶段：类型与测试补齐

重点补充：

1. 页面会话切换测试。
2. 旧请求回包测试。
3. 新建提交后的单次加载测试。
4. 默认标签计算测试。
5. 逻辑图复用流程图画布测试。
6. 视口配置缺失和接口失败测试。
7. 画布组件实例引用类型收紧。

当前进展：

1. 已补详情加载成功、失败和过期请求测试。
2. 已补通用弹窗会话、树抽屉会话和分栏会话测试。
3. 已收紧画布舞台、视口运行时和详情加载器的关键类型。
4. 页面数据监听与画布会话监听暂不继续合并，当前边界已能分别表达页面加载和画布初始化职责。

## 四、实施顺序

```text
页面状态模型
  ↓
页面数据会话与画布会话拆分
  ↓
详情数据加载入口收敛
  ↓
视口初始化逻辑抽离
  ↓
事件与协作生命周期整理
  ↓
模板组件拆分
  ↓
状态模块拆分
  ↓
类型与测试补齐
```

每个阶段单独验证，避免一次性大范围重构导致页面加载、画布切换和协作功能同时出现回归。

## 五、明确不纳入首轮重构的内容

1. 不优先调整全局请求拦截器。
2. 不在首轮大规模改动子画布组件。
3. 不因为形式统一而将所有组合式函数移动到挂载钩子中。
4. 不优先处理窗口高度常量和微小节流优化。
5. 不在未稳定页面会话之前拆分过多展示组件。
