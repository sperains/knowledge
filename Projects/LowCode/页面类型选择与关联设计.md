# LowCode 页面类型选择与关联设计

> 本文是详细说明文档，正式架构决策见 [[ADR/ADR-015-页面类型创建时确定并通过页面编号关联]]。

## 1. 当前结论

当前阶段只保留两种页面类型：

- 列表页：查询和管理多条业务数据。
- 表单页：创建或编辑一条业务数据。

页面类型应在创建页面时指定，编辑器中只展示当前类型，不提供普通的类型切换入口。

## 2. 为什么在创建时指定

列表页和表单页不是简单的样式差异，而是两种不同的页面模型：

- 列表页包含查询条件、数据列表、分页和行操作。
- 表单页包含字段、校验、提交和编辑模式。

如果允许在编辑器中直接切换，需要处理原有配置转换、不兼容字段、数据丢失和预览逻辑变化，早期项目不值得承担这部分复杂度。

页面创建流程统一为：

```text
新建页面 → 选择列表页或表单页 → 保存页面类型 → 加载对应编辑器
```

页面类型创建后作为页面基础属性保存，不建议在页面已经产生配置后随意切换。

## 3. 类型变更策略

页面编辑器顶部展示当前页面类型，但不提供常规切换操作。

如果用户误选类型，后续提供以下安全操作：

- 复制为列表页。
- 复制为表单页。
- 仅在页面没有任何配置时允许更换类型，并要求二次确认。

不直接把列表页配置转换为表单页配置，也不直接把表单页配置转换为列表页配置。

## 4. 列表页与表单页的关系

表单页通常是列表页的附属页面，但附属关系不代表表单页不需要访问路径。表单页仍需要独立路径，以支持刷新、前进后退、预览、权限控制和异常恢复。

一个列表页可以关联一个表单页：

```text
列表页
├── 新建 → 关联表单页
└── 编辑 → 关联表单页
```

新建和编辑共用同一个表单页，通过访问参数区分模式：

```text
/users/form?mode=create
/users/form?mode=edit&id=abc123
```

- `mode=create` 表示新建，表单默认为空。
- `mode=edit` 表示编辑，通过 `id` 加载已有记录。
- `id` 是业务数据编号，不使用页面编号替代。

## 5. 关联规则

列表页配置保存关联表单页的页面编号，而不是页面名称或访问路径：

```ts
{
  pageType: 'list',
  resourceKey: 'user',
  formPageId: '页面编号'
}
```

列表页和表单页需要使用相同的 `resourceKey`：

```text
列表页 resourceKey：user
表单页 resourceKey：user
```

这样可以避免用户列表错误关联到订单表单。

## 6. 路径与菜单

表单页保留访问路径，但默认不作为主菜单入口：

```text
列表页：/users
表单页：/users/form
```

后续可以通过页面属性控制是否显示在菜单中。即使表单以弹窗或抽屉形式打开，也建议保留内部路径作为预览、刷新和异常恢复的兜底入口。

## 7. 页面跳转闭环

```text
列表页
  ↓ 新建或编辑
表单页
  ↓ 提交成功
返回列表页并刷新
```

第一期采用固定目标页面编号返回，不设计复杂的历史路由恢复和多级返回链路。
