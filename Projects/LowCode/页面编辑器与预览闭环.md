# 页面编辑器与预览闭环

> 本文记录当前落地状态，页面配置持久化和页面类型的正式架构约束见 [[ADR/ADR-014-页面配置采用JSON版本化持久化]] 和 [[ADR/ADR-015-页面类型创建时确定并通过页面编号关联]]。

## 文档定位

本文记录 LowCode 项目当前已经落地的页面管理、页面编辑器和页面预览能力，作为后续继续开发的上下文依据。

当前阶段的目标不是构建完整的企业级低代码平台，而是先打通：

```text
创建项目 → 创建页面 → 编辑页面 → 保存配置 → 预览页面
```

## 页面路由

| 页面 | 路径 | 作用 |
|---|---|---|
| 项目管理 | `/projects` | 管理全部项目、创建项目和进入项目中心 |
| 项目概览 | `/projects/:projectId` | 查看项目概况和快捷入口 |
| 页面管理 | `/projects/:projectId/pages` | 管理项目页面、创建页面和进入编辑器 |
| 页面编辑器 | `/projects/:projectId/pages/:pageId/editor` | 配置页面组件和保存页面 |
| 页面预览 | `/projects/:projectId/pages/:pageId/preview` | 查看已保存页面的运行效果 |
| 项目设置 | `/projects/:projectId/settings` | 管理项目基础设置 |

页面编辑器使用沉浸式布局：进入编辑器后隐藏项目中心的顶部栏和左侧项目菜单，保留编辑器自身的页面面包屑作为返回入口。项目概览、页面管理和项目设置继续使用项目中心布局。

页面预览使用独立布局，不显示项目中心菜单，避免把项目管理导航带入最终应用展示区域。

当前列表页编辑器与预览约束：

- 列表页编辑器与预览共用列表页配置模型，筛选条件、工具栏、数据表格、行操作和分页保持同一份结构。
- 列表内容区不重复显示页面 Header；页面标题和简介保留在页面设置中，供后续运行时展示使用。
- 编辑器和预览均聚焦筛选工具栏与实际数据区域，筛选字段过多时自动换行。

## 编辑器布局

编辑器采用三栏工作台结构：

```text
┌──────────────┬────────────────────────┬──────────────┐
│ 组件面板      │ 页面画布                 │ 属性面板      │
│              │                          │              │
│ 基础组件      │ 页面承载面               │ 选中组件信息  │
│ 点击添加      │ 组件选中状态             │ 基础属性      │
│              │                          │ 删除操作      │
└──────────────┴────────────────────────┴──────────────┘
```

### 组件面板

当前提供三类基础组件：

- 文本：标题或说明文字。
- 按钮：用于触发操作的基础按钮。
- 输入框：接收用户输入。

当前采用点击添加，暂未实现拖拽添加。这样可以先验证页面配置模型和编辑闭环，避免过早引入复杂的画布交互。

### 页面画布

- 使用白色页面承载面模拟实际应用页面。
- 外层使用点阵工作区区分编辑区域和页面区域。
- 组件可以被选中，选中后显示类型标签和操作提示。
- 画布中的组件展示效果与预览页面共用同一套组件渲染逻辑。

### 属性面板

当前只提供基础文本属性：

- 文本组件配置显示文字。
- 按钮组件配置显示文字。
- 输入框组件配置占位文字。

修改属性后立即同步画布，并通过页面顶部状态提示区分“已保存”和“未保存更改”。

## 页面配置结构

当前页面配置保持简单，页面版本中的配置使用 JSON 保存：

```json
{
  "components": [
    {
      "id": "组件唯一标识",
      "type": "text",
      "props": {
        "text": "这是一段文本"
      }
    }
  ]
}
```

当前约定：

- `components` 保存页面组件列表。
- `id` 使用 NanoID，前端编辑器负责生成临时组件标识。
- `type` 表示组件类型。
- `props` 保存组件属性。
- 编辑器和预览使用同一份页面配置。
- 样式、事件、数据绑定和子组件结构暂不提前固定，待真实需求出现后扩展。

列表页使用独立的配置结构，但仍保存于页面版本 JSON 中：

```json
{
  "pageType": "list",
  "title": "员工管理",
  "description": "查询、管理和维护员工数据。",
  "resourceKey": "employees",
  "formPageId": "表单页编号",
  "filters": [],
  "toolbar": {
    "showCreate": true,
    "showRefresh": true
  },
  "table": {
    "columns": [],
    "rowActions": {
      "showEdit": true,
      "showDelete": false
    },
    "pagination": {
      "enabled": true,
      "pageSize": 10
    }
  }
}
```

列表页配置约束：

- `title` 和 `description` 是页面展示元数据，不直接决定页面路由。
- `resourceKey` 用于表达列表页和表单页管理的业务资源。
- `formPageId` 保存关联表单页的页面编号，不使用页面名称或路径作为稳定关联键。
- `filters`、`toolbar`、`table` 只描述列表页自身能力，不提前引入真实数据源查询协议。

## 编辑器与预览的共享机制

页面编辑器和页面预览都使用统一的组件渲染器：

```text
页面配置
   ↓
统一组件渲染器
   ├── 编辑器画布：只读展示 + 选中框
   └── 页面预览：实际展示 + 输入交互
```

这样可以避免编辑器和预览分别维护一套组件展示逻辑，降低两边显示不一致的风险。

当前预览规则：

- 预览读取后端已保存的页面配置。
- 编辑器存在未保存修改时，点击预览会先自动保存。
- 文本和按钮按照页面配置展示。
- 输入框在预览状态下允许输入。
- 按钮暂时只有视觉展示，具体事件动作后续配置。

列表页预览规则：

- 预览提供桌面端和移动端切换。
- 桌面端使用最大宽度 `1120px` 的自适应容器，不强制模拟 `16:9` 画布，高度由内容决定。
- 移动端使用约 `390px` 的内容宽度，并将筛选字段切换为单列布局。
- 列表内容区直接聚焦筛选工具栏和数据表格，不重复显示内部页面 Header。
- 分页作为数据表格区域的一部分展示，不拆成独立页面区块。
- 筛选字段和操作按钮保持同一工具区域；字段过多时自动换行。

## 页面接口

页面相关接口保持统一响应结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

当前页面编辑器使用：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/pages/{page_id}` | 读取页面基础信息和当前配置 |
| `PUT` | `/api/pages/{page_id}` | 保存页面配置并生成页面版本 |

页面创建和项目页面列表接口记录在《数据库设计》中。

## 当前技术约束

- 前端使用 Vue 3、TypeScript、Vite 和 Arco Design Vue。
- 后端使用 FastAPI、SQLModel 和 SQLite。
- 页面配置由后端保存，前端不直接操作数据库。
- 前后端资源唯一标识统一使用 NanoID。
- 页面编辑器暂不引入独立状态管理，先使用页面级响应式状态完成闭环。
- 预览页暂不承担发布、部署和访问权限职责。

## 下一步建议

按照低复杂度优先的原则，后续建议按以下顺序推进：

1. 将组件目录抽离为统一的组件注册表和元数据定义。
2. 增加组件排序和简单拖拽能力。
3. 为按钮、输入框增加更多基础属性。
4. 增加页面预览中的按钮事件配置。
5. 增加设备尺寸切换和基础响应式预览。
6. 再评估发布、菜单绑定、数据源和权限等平台能力。

暂不建议立即引入复杂画布引擎、撤销重做、协同编辑、插件市场和多租户模型。
