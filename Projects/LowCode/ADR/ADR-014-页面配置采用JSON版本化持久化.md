# ADR-014 页面配置采用 JSON 版本化持久化

- 状态：Accepted
- 日期：2026-08-03
- 作者：Codex
- 相关领域：页面模型、数据库、配置持久化

## 背景（Context）

低代码编辑器的组件类型、属性和布局会持续变化。早期如果为每个组件和每个属性建立关系表，模型会被当前组件集合绑定，迁移成本高，也会拖慢编辑器闭环的验证。项目当前更需要配置结构灵活、保存简单，并能支持预览读取。

## 考虑方案（Options）

1. 将组件树、组件属性和样式全部拆成关系表，查询明确，但表数量和迁移成本较高。
2. 将整页配置保存为 JSON，页面基础信息和版本信息仍使用关系表，结构灵活且实现简单。
3. 只保存当前配置，不保留版本，最简单，但无法支持版本回退和编辑历史。

## 决策（Decision）

采用“关系表保存页面基础信息，JSON 保存页面配置，页面版本保存每次有效配置”的方案：

- `page` 保存页面名称、页面类型、访问路径和当前版本等基础信息。
- `page_version` 保存组件树、属性、样式等完整页面配置 JSON。
- 每次页面保存创建新的页面版本，并更新页面当前版本指向。
- 编辑器和预览共用同一份已保存配置及组件渲染器。
- 配置结构由应用层校验，组件元数据负责约束可编辑属性。

## 后果（Consequences）

正面影响：组件配置可以快速演进；数据库模型保持少而稳定；保存和预览使用同一份配置，闭环清晰。

负面影响：复杂 JSON 查询不如关系表直接；配置合法性需要应用层校验；版本数量增长后需要考虑清理、归档或存储优化。

## AI 指导原则

- 页面基础属性和页面版本配置必须保持职责分离。
- 新增组件属性优先通过组件元数据和配置校验承接，不为单个属性创建数据库字段。
- 保存、预览和版本读取优先复用现有页面配置接口。
- 只有在出现明确的查询、性能、协作或审计需求时，才评估拆分关系表或引入专用存储。
