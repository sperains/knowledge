# LowCode 项目数据库设计

> 本文是数据库详细设计说明，页面配置持久化的正式架构决策见 [[ADR/ADR-014-页面配置采用JSON版本化持久化]]。

## 1. 设计目标

当前项目以快速验证低代码核心流程为目标，数据库设计遵循“少表、可演进、配置灵活”的原则：

- 使用 SQLite 支撑本地开发和单机演示。
- 使用 SQLModel 描述模型，使用 Alembic 管理表结构变更。
- 页面组件树以 JSON 保存，避免在早期拆分大量组件明细表。
- 项目、页面和页面版本保持清晰的层级关系。
- 暂不引入用户、权限、数据源和工作流等复杂模型。

## 2.1 唯一标识规范

前后端统一使用 NanoID 作为新建资源的唯一标识：

- 后端负责生成项目、页面和页面版本的持久化 ID。
- 前端使用 NanoID 生成编辑器中的临时组件 ID。
- 默认长度为 21，类型统一为字符串。
- 现有数据库中的旧 UUID 不迁移，避免破坏已有引用。

项目展示标识 `code` 由后端根据项目名称自动生成，始终只包含英文大写字符：

- 中文名称取前两个汉字的拼音首字母，例如“客户门户”生成 `KH`。
- 英文名称取单词首字母，例如“Customer Portal”生成 `CP`。
- 单个英文单词取前四个字符，例如“LowCode”生成 `LOWC`。
- 无法提取有效字符时使用 `LC`。
- `code` 只用于展示，不承担唯一性；资源唯一性由 `id` 保证。

## 2. 核心关系

```text
项目 project
  ├── 页面 page
  │     └── 页面版本 page_version
  └── 项目配置 project_settings
```

当前数据库中的物理表使用单数命名，便于与 SQLModel 默认表名保持一致。

## 3. 表结构

### 3.1 项目表 `project`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 | 主键，使用唯一标识 |
| `code` | 字符串 | 项目卡片展示缩写 |
| `name` | 字符串 | 项目名称 |
| `description` | 字符串 | 项目描述 |
| `status` | 字符串 | 草稿、运行中等项目状态 |
| `created_at` | 日期时间 | 创建时间 |
| `updated_at` | 日期时间 | 最后修改时间 |

### 3.2 页面表 `page`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 | 主键 |
| `project_id` | 字符串 | 所属项目 |
| `name` | 字符串 | 页面名称 |
| `route` | 字符串 | 页面访问路径 |
| `page_type` | 字符串 | 页面类型，列表页或表单页 |
| `status` | 字符串 | 草稿、已发布等页面状态 |
| `sort_order` | 整数 | 页面排序值 |
| `created_at` | 日期时间 | 创建时间 |
| `updated_at` | 日期时间 | 最后修改时间 |

### 3.3 页面版本表 `page_version`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 | 主键 |
| `page_id` | 字符串 | 所属页面 |
| `version` | 整数 | 页面版本号，从 1 开始递增 |
| `schema_json` | 文本 | 页面组件树和配置 JSON |
| `status` | 字符串 | 草稿、已发布等版本状态 |
| `created_at` | 日期时间 | 版本创建时间 |

页面保存时，如果提交了新的组件配置，就创建一个新的页面版本；页面基础信息则直接更新到 `page` 表。

### 3.4 项目配置表 `project_settings`

| 字段 | 类型 | 说明 |
|---|---|---|
| `project_id` | 字符串 | 主键，同时关联项目 |
| `theme_json` | 文本 | 项目主题和样式配置 |
| `routing_json` | 文本 | 项目路由相关配置 |
| `updated_at` | 日期时间 | 最后修改时间 |

项目配置暂时只保留两个 JSON 扩展字段，后续根据真实需求再拆分。项目卡片颜色等界面样式由前端根据项目 ID 稳定计算，不写入项目主表。

## 4. 页面配置格式

页面版本中的 `schema_json` 暂采用组件树结构：

```json
{
  "components": [
    {
      "id": "button_1",
      "type": "button",
      "props": {
        "text": "提交"
      },
      "style": {
        "width": "120px"
      },
      "children": []
    }
  ]
}
```

约定如下：

- `id` 在同一个页面版本内唯一。
- `type` 对应前端组件注册表中的组件类型。
- `props` 保存组件属性。
- `style` 保存组件样式配置。
- `children` 保存容器组件的子组件。
- 组件事件、数据绑定和条件渲染先作为后续扩展字段，不提前固定表结构。

### 4.1 列表页配置格式

列表页和普通组件页面一样使用 `schema_json` 保存，但根据 `page_type` 使用不同的配置结构：

```json
{
  "pageType": "list",
  "title": "员工管理",
  "description": "查询、管理和维护员工数据。",
  "resourceKey": "employees",
  "formPageId": "表单页编号",
  "filters": [],
  "toolbar": {
    "showCreate": true,
    "showRefresh": true
  },
  "table": {
    "columns": [],
    "rowActions": {
      "showEdit": true,
      "showDelete": false
    },
    "pagination": {
      "enabled": true,
      "pageSize": 10
    }
  }
}
```

列表页配置只保存页面结构和展示行为，不保存真实数据记录。`title`、`description` 用于后续页面展示，`resourceKey` 用于业务资源语义校验，`formPageId` 用于关联列表页对应的表单页。

## 5. 数据访问接口

当前已提供页面基础接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/projects/{project_id}/pages` | 查询项目页面 |
| `POST` | `/api/projects/{project_id}/pages` | 创建页面并生成首个版本 |
| `GET` | `/api/pages/{page_id}` | 查询页面及当前版本配置 |
| `PUT` | `/api/pages/{page_id}` | 更新页面并按需生成新版本 |

接口继续使用统一响应结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

## 6. 迁移规范

数据库结构由 Alembic 管理：

```bash
cd apps/api
uv run alembic upgrade head
```

应用启动时也会自动执行 `upgrade head`，用于简化本地开发。新增字段或表时，应新增迁移文件，不直接修改历史迁移。

## 7. 暂不设计的内容

以下内容保留到后续真实需求明确后再设计：

- 用户、团队和项目成员权限。
- 数据源、数据表和接口连接器。
- 页面访问权限和角色权限。
- 工作流、定时任务和事件编排。
- 操作历史、撤销重做和协同编辑。
- 发布环境、域名和部署记录。

这样可以避免在页面编辑器尚未稳定前过早固化复杂领域模型。
