# 参观模式接口契约草案

状态：前端提案，待后端确认和实现。下列接口和字段目前并不存在，不能视为已联调。

## 业务规则

- 管理员管理中按管理员账号设置参观模式，设置由服务端持久化；默认关闭是接口草案建议，尚未确认。
- 开启后，客户名称和用户名称均显示该条数据对应的 `society2`；字段缺失或为空时显示 `--`。登录人的姓名不属于企业名称。
- 管理员 A 修改管理员 B 的设置后，B 的所有已登录页面需要检测到变更并刷新；成功修改自己的设置时，当前页面也刷新。
- 名称替换的当前清单范围为大屏第 1–16 项及消息页面；用户排除原清单第 17–20 项和后台管理页面。后台管理员管理中的开关仍属于需求。具体页面位置和接口核对以 [Excel 明细](./参观模式名称使用明细.xlsx) 为准。
- 企业名称原值仍用于已有查询、跳转和业务参数，不在前端全局改写接口原始数据。

## 建议接口

使用现有响应包裹格式 `{ "code": 0, "data": ... }`。以下路径、字段及权限均为提案。

### 管理员列表

现有 `POST /api_java/admin/system/userList` 的每条管理员记录增加：

```json
{ "id": 123, "visitMode": false }
```

`visitMode` 为布尔值；历史账号未设置时服务端返回 `false`。

### 修改指定管理员设置

建议新增 `POST /api_java/admin/system/setVisitMode`：

```json
{ "id": 123, "visitMode": true }
```

成功返回该账号的最新状态和版本：

```json
{ "code": 0, "data": { "visitMode": true, "version": "42" } }
```

服务端校验操作人管理权限；仅当值实际变化时，原子地持久化并更新版本。失败时不得返回成功，前端保持原开关状态。该接口只更新参观模式，不覆盖角色、密码或其他配置。

### 获取当前登录账号设置

建议新增 `GET /api_java/admin/system/visitMode`，从认证信息确定账号，不接收用户 ID：

```json
{ "code": 0, "data": { "visitMode": true, "version": "42" } }
```

`version` 为账号范围内不透明的字符串，每次设置实际变化后改变；即使开关先开再关，也必须得到新版本。接口禁止缓存。登录和刷新页面后，前端在展示业务数据前读取该接口；读取失败时不能沿用可能过期的关闭状态展示名称，应提示重试。

已登录页面建议每 5 秒轮询一次，并在页面重新可见时立即检查。发现版本变化后刷新页面；刷新后的首次读取以服务端最新版本作为基线，避免重复刷新。后台标签页受浏览器节流影响，恢复可见时立即检查；离线期间无法保证即时刷新，恢复连接后检查。轮询失败保留原版本并重试，不因失败循环刷新。登录失效按现有认证流程处理。

## 业务数据

建议在清单范围内，为展示客户名称或用户名称的数据对象提供对应的 `society2` 字符串，包括嵌套列表和详情。保留原有 `c_name`、`customer_name`、`uc_name` 等字段及查询语义。信用代码缺失时返回 `null` 或空字符串；不要使用客户 ID、设备 ID 或其他主键代替。前端已有部分接口将 `society2` 注释为用户主键，后端需核对其实际含义及现有请求参数的兼容性。

已核对的首页实时消息和用户列表响应包含 `society2`；其中用户列表出现过 `885`，不能仅因字段名就断定其值符合统一社会信用代码格式。阈值详情响应中的 `society2` 为 `null`；空试、投运和模块投运记录的已提供响应未包含该字段。上云登记记录返回 `cCode`，页面标为社会统一代码，是否将其作为替代字段仍需确认。其余页面的具体数据与类型状态见 [Excel 明细](./参观模式名称使用明细.xlsx)。

## 联调验收

1. 验证管理员列表、单独保存、默认关闭、权限拒绝和保存失败回滚。
2. 两个浏览器分别登录同一被修改账号，操作人修改开关后，两端均检测版本并刷新；刷新后读取最新状态且不循环刷新。覆盖连续开关、离线恢复和登录失效。
3. 覆盖清单范围内的各名称、列表、详情、下拉框和提示；有代码显示代码，缺失显示 `--`，关闭后恢复名称。检查搜索、跳转、编辑和提交仍使用原有业务值。
