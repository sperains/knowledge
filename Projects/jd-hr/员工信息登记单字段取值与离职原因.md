# 员工信息登记单字段取值与离职原因

本文记录 2026-10-29 确认的离职原因需求，以及同日基于 jd-hr 前端代码梳理的字段取值；后端行为以联调验证为准。前端源码基线包含未提交的工作区改动，不能将其视为已发布版本。

## 数据与权限的共同入口

- `bus/user/get-detail` 返回顶部员工数据和当前模块数据：顶部字段权限为 `data.form_field_list`，模块数据为 `data[模块标识]`，模块字段权限为该对象的 `form_field_list`；有子模块时由 `nav_list` 提供子模块权限和 `list`，前端将 `form_field_list` 映射为 `form_field`。
- 保存 `bus/user/save` 时，顶部表单展开到 `row`，当前模块的表单或列表放入 `row[模块标识]`。字段定义与具体调用见 `src/views/staffMmt/editor.vue` 和 `src/api/staffMmt/index.ts`。
- 字段权限 `permission_code`：0 无权限、1 查看、2 编辑。`FormItemRight` 只有编辑权限才传入字段校验规则；无权限的展示需脱敏。关联词云以权限配置中的 `relation_business_no` 获取关联选项。
- 单值表单编辑通常绑定 `formValue[field]`，从详情对象同名字段初始化；普通只读展示先使用字段 `computed`（若有），否则依次取权限配置 `field_value_label`、传入的详情字段、表单值。未传详情对象时不能从详情对象回退。自定义插槽和年限类型有自己的展示方式。
- 表格使用 `FormTable`，编辑和查看以行 `record[dataIndex]` 为基础；只读时根据类型处理选项、金额、开关、年月或附件。权限配置按列控制编辑和展示，并非每一行的值来源。

## 顶部员工信息

顶部表单通常从详情顶层字段初始化，字段标题和权限取顶层 `form_field_list`。普通只读字段姓名 `user_name`、主体 `subject_id` / `subject_name`、工号 `work_number`、所属部门 `department_id` / `department_name` 走通用展示优先级；部门选项来自部门树接口。新建时主体 ID 来自当前登录主体。

头像 `user_avatar` 直接使用表单值并按权限显示；手机 `phone`、岗位 `job_id`、员工状态 `user_status`、在岗状态 `job_status` 的只读展示使用各自的 `computed`，分别读取手机值、提取岗位名称、拼接状态路径，不走普通 `field_value_label` 优先级。离职时在岗状态隐藏并清空。

### 离职原因

已确认的业务规则：

- 选择“离职 → 辞退”时显示 `resignation_reason`，必须输入非空自由文本，不限制字数；切换到其他状态时清空。按没有同名层级处理。
- 只读查看时长文本显示省略号，鼠标移入显示全文；无查看权限时不得通过提示泄露内容。人员列表或导出未来需要展示，但当前列表字段由接口返回，本次不处理列表前端。
- 用户提供的字段配置中 `field_value` 是原始值，`field_value_label` 可为空。当前实现初始化时优先读 `form_field_list.resignation_reason.field_value`，缺失时回退顶层同名详情字段；编辑和只读使用表单值。提交时仅对有编辑权限的用户包含该字段。
- 新增字段规则交由顶部表单 `formRef.validate()` 统一校验空值及纯空格；但通用组件只给编辑权限字段传校验规则。`permission_code: 1` 仅查看，不能填写。
- 输入类必填提示采用“请输入”，选择类采用“请选择”。

**待后端核实与联调**：保存及详情接口是否完整支持该字段、权限配置是否位于顶部字段列表、无编辑权限时未提交字段能否保留原值、切到其他状态时服务端是否清空、辞退时服务端是否校验必填并给无编辑权限用户明确提示、无查看权限时是否不返回明文。历史辞退记录不做额外迁移处理，保存时按必填规则执行；上述服务端行为尚未由当前前端仓库证明。

## 基本信息 `userBase`

模块字段从 `data.userBase` 初始化；普通只读字段优先模块字段配置的 `field_value_label`，再回退表单值。`src/views/staffMmt/components/card/baseInfo/index.vue` 中的特殊字段如下：

- 性别 `sex`、入职日期 `enter_date`、离职日期 `resignation_date`、身份证号 `user_IDCard`、籍贯 `hometown` / `hometown_name`、民族 `nationality`、政治面貌 `political_appearance`、婚姻状况 `marital`、户口类型 `household_type`、户籍地址 `household_address`、车牌 `car_number`、介绍人或渠道 `introduction_person`、企业微信 `short_name`、内外部能力评价 `internal_ability_evaluation` / `external_ability_evaluation`：从同名模块详情初始化，选择项依类型来自配置或关联词云。
- 岗位分类 `job_class`、职等 `job_level`、职级 `job_grade`：只读展示与顶部岗位联动，通过员工 store 取值，保存有 store 值兜底。
- 出生日期 `birthday`：详情初始化，身份证输入符合规则时从身份证号码提取。身份证有效期使用 `user_IDCard_start_date`、`user_IDCard_end_date`、`user_IDCard_long_effective` 自定义展示，保存生成 `user_IDCard_valid_date`。
- 学历和院校 `day_highest_education`、`day_graduation_college`、`highest_education`、`graduation_college` 是只读详情字段，页面说明来源于教育经历。地址 `address`、`longitude`、`latitude` 可由地图选择同步。
- 入职前年限 `work_before_year`、当前职位年限 `work_current_year`、司龄 `work_year` 以月数初始化并拆成年月；日期变化触发年限计算。`work_effective_date` 是当前职位生效日期，离职日期仅离职状态可编辑。
- 身份证正反面 `user_card_front` / `user_card_back`、驾驶证 `driving_license`、行驶证 `driving_permit` 使用自定义附件插槽，直接从表单取值。

## 带子模块的登记单

- **薪酬福利 `userSalaryBenefits`**：单值字段 `wage_type`、`performance_type`、`social_security_pay_base`、`annual_ave_social_wage` 从模块详情初始化。工资 `userSalary` 子列表包含 `item`、`class`、`secrecy_level`、`is_provide`、`money`、`start_date`、`end_date`、`note`；社保 `userSocialSecurity` 子列表还包含 `social_ratio`、`payment_months`、`payment_place`。子列表从对应 `nav_list` 项的 `list` 初始化，社保比例和金额存在主体配置及计算逻辑，合计由前端从明细计算。
- **证书信息 `userCertificate`**：职业资格 `userCertificateQualification` 行字段为 `qualifocate_type`、`qualifocate_class`、`qualifocate_name`、`qualifocate_level`、`operation_items`、`major`、`certificate_number`、`register_number`、`is_annual`、`start_date`、`end_date`、`authority`、`certificate_file`；其他证书 `userCertificateOther` 为 `certificate_name`、`certificate_type`、`certificate_level`、`certificate_number`、`authority`、`interrogation_date`、`start_date`、`end_date`、`certificate_file`、`note`；残疾证 `userCertificateDisability` 为 `disability_type`、`disability_level`、`disability_number`、`start_date`、`certificate_validity`、`authority`、`is_validity`、`certificate_file`、`note`。各自取子模块 `list` 行值。
- **领取物品 `userGoods`**：基础 `userItem` 的行字段为 `type_id`、`class_id`、`stock_number`、`stock_name`、`stock_model`、`stock_unit`、`consuming_date`、`consuming_num`、`code`、`note`；印章 `userSeal` 为 `class_id`、`seal_number`、`seal_unit`、`consuming_num`、`consuming_date`、`note`；U 盾及密钥 `userSecret` 为 `secret_name`、`secret_url`、`account`、`secret_type`、`secret_number`、`secret_num`、`secret_unit`、`certificate_validity`、`consuming_date`、`note`。选择存货可带出编码、名称、规格和单位，单位名称由单位列表转换。
- **涉及系统 `userSystem`**：内部系统直接展示子模块列表的 `icon`、`system_name`、`url`；外部系统行字段为 `type`、`system_name`、`url`、`account`、`login_type`、`registration_date`、`stop_date`、`authorized_start_date`、`authorized_end_date`、`role`、`cardId`、`phone`、`customer_code`、`operation_code`、`login_pass`、`note`。当前保存结果组装外部系统数据。
- **信用等级 `userCreditRating`**：当前前端仅为空状态，校验返回空对象，没有字段取值实现。

## 统一取值时的边界

`field_value`、`field_value_label`、详情顶层值、列表行值和前端派生值各有职责。不能直接将所有字段改为从字段权限配置取值：表格配置按列而数据按行，岗位及状态等字段需要原始路径供编辑和联动。跨字段统一之前，应先核对各接口实际返回契约；本文不将离职原因的 `field_value` 约定推广为所有字段已经采用的规则。
