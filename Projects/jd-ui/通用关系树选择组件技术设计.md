# 通用关系树选择组件技术设计

## 1. 技术选型

组件使用 Arco 的 `a-tree-select` 作为交互内核，使用自定义 `trigger` 插槽实现输入框回显。

Arco 负责弹层定位、树展开、基础选择、搜索、多选状态和键盘交互。组件自身负责关系数据归一化、历史值回显、路径显示、节点样式和加载结果事件。

原有 `jd-relation-select` 不参与本次迁移，新增组件独立注册为 `jd-relation-select-java`。

## 2. 模块划分

源码目录：

~~~text
packages/jd-design/src/components/jd-relation-select-java/
├── index.vue                         组件入口和 Arco 适配
├── types.ts                          数据类型和归一化函数
├── use-relation-tree.ts              请求、树归一化和显示计算
├── use-relation-selection.ts         v-model、选中值和历史值匹配
├── RelationSelectTrigger.vue         自定义输入框触发器
└── RelationSelectNodeTitle.vue       下拉树节点标题
~~~

### 2.1 `index.vue`

负责：

- 组合 Arco `a-tree-select`。
- 透传常用属性和树配置。
- 监听弹层开关，并触发每次打开的数据请求。
- 转发选择、搜索、清空、移除和加载结果事件。
- 根据 `allowParentSelect`、`disableLevels` 和叶子状态计算节点可选性，并在选择回调中再次拦截非法值。
- 将树状态、选中状态和触发器展示状态组合起来。

### 2.2 `use-relation-tree.ts`

负责：

- 调用 `getDataFn(relationNo)`。
- 校验关系对象和 `children`。
- 递归生成节点路径。
- 构建下拉树和扁平节点列表。
- 计算文本模式、路径模式和显示层级。
- 维护原始响应树，在选择策略变化时重新生成标准化树和节点可选状态。
- 维护请求序号，避免旧请求覆盖新请求。

### 2.3 `use-relation-selection.ts`

负责：

- 将外部 `modelValue` 转换为 Arco 使用的节点键值。
- 根据树数据查找当前节点。
- 按 `id`、`word_id` 和路径文本匹配历史值。
- 在当前节点存在时使用最新节点替换旧值。
- 在当前节点不存在时保留历史节点。
- 按主键、业务编号、节点标识和完整路径匹配历史值。
- 校验层级禁选和父节点选择规则，避免外部回写绕过树组件的可选性限制。
- 生成不包含 `children` 的对外节点值。

### 2.4 `RelationSelectTrigger.vue`

负责：

- 渲染默认占位文本、搜索输入和选中值。
- 统一处理单选和多选的展示模板。
- 渲染文本模式和路径模式。
- 为路径节点分别应用文字、背景和边框样式。
- 提供 Arco 风格的清空按钮、删除按钮和悬浮效果。

## 3. 数据处理流程

### 3.1 打开下拉

~~~text
popupVisible: false -> true
        |
        v
生成 requestId
        |
        v
loading = true
        |
        v
调用 getDataFn(relationNo)
        |
        +--> 请求异常 ------------------> load-error
        |
        v
校验关系对象和 children
        |
        +--> null / undefined ----------> 清空树 + load-empty(empty-response)
        |
        +--> children: [] --------------> 清空树 + load-empty(empty-children)
        +--> children 缺失或非数组 -----> 清空树 + load-empty(empty-children)
        |
        v
递归归一化树并生成 paths
        |
        v
替换内部树，重新匹配 modelValue
        |
        v
loading = false
~~~

每次打开都重新执行上述流程。请求成功后使用本次响应替换旧树，不做基于 `relationNo` 的缓存。

### 3.2 过期请求

每次请求递增 `dataRequestId`。响应返回后只有当响应携带的请求序号仍然等于当前序号时，才允许：

- 更新树数据。
- 更新加载状态。
- 触发空数据或错误事件。
- 同步历史值。

过期请求直接丢弃，不能覆盖后发请求。

### 3.3 选择策略变化

`allowParentSelect` 默认为 `false`，父节点默认只能展开；设置为 `true` 后父节点才可选择。`disableLevels` 从根节点开始按 1 计算，优先级高于父节点可选配置，只禁止指定层级更新值，不影响展开。树数据更新后，选择组合函数还会再次校验节点层级和父子关系，防止外部回写或内部事件绕过 `selectable` 回调。

## 4. 树数据归一化

### 4.1 路径快照

递归处理节点时，将当前祖先路径和当前节点快照合并：

~~~text
父节点 paths + 当前节点快照 = 当前节点完整 paths
~~~

路径快照会删除 `children`、旧 `paths` 和树组件内部字段，保留节点文本、样式和业务字段。

### 4.2 内部树和外部值

内部树保留 `children`，用于 Arco 展开和搜索。

外部选中值通过 `normalizeRelationNodeValue` 生成：

- 删除 `children`。
- 补充标准节点字段。
- 写入节点对象数组形式的 `paths`。
- 保留其他业务字段。

## 5. 历史值匹配

历史值和当前树数据分开维护。当前树只代表最新可选项，历史值用于保持表单回显。

匹配顺序：

1. 节点键值匹配，当前实现使用 `id`。
2. `word_id` 或节点 `id` 交叉匹配。
3. `paths` 中的节点文本按顺序完全匹配。

匹配成功后，将外部值替换为最新节点并重新生成路径。匹配失败时，不从 `modelValue` 中删除历史节点，触发器继续使用历史对象展示。

## 6. 显示计算

`use-relation-tree.ts` 提供三个层次的显示计算：

- `pathNodes`：取得完整节点路径。
- `displayPathNodes`：按 `displayLevel` 截取路径节点。
- `displayLabel`：文本模式显示目标层级文本，路径模式使用 `separator` 拼接文本。

路径模式下，触发器同时使用 `displayPathNodes` 和每个路径节点的样式，保证路径中不同节点的样式不会被合并成一个整体样式。

## 7. 选择和搜索

### 7.1 父节点选择

`allowParentSelect` 控制 Arco 的 `selectable` 和树的 `actionOnNodeClick`：

- `true`：父节点可以直接选择，但仍受 `disableLevels` 限制。
- `false`：父节点设置为不可选，点击节点执行展开行为；叶子节点仍可选择。

### 7.2 层级禁选

`disableLevels` 使用从根节点开始的一级编号。层级被禁止时，节点保留展开能力，但不能更新 `v-model`；层级策略变化时，组件从原始响应树重新计算状态，避免在已标记的展示树上叠加旧状态。

### 7.3 搜索父节点

归一化后的每个节点都带有 `paths`。过滤时遍历路径节点文本，而不是把节点对象直接转换成字符串。这样搜索命中父级路径时，父节点和后代仍能保留在树中，父节点可以继续展开。

## 8. 事件设计

组件不绑定具体弹窗实现，只发出状态事件：

~~~ts
load-empty: {
  relationNo: string;
  reason: 'empty-response' | 'empty-children';
  response: RelationResponse | null | undefined;
}

load-error: {
  relationNo: string;
  error: unknown;
}
~~~

`load-empty` 用于请求完成但没有可选节点，包括关系对象整体为空、`children` 为空或缺少 `children`；`load-error` 只用于请求异常。使用方可以在事件处理器中调用 Arco Message、Notification 或业务自己的提示服务。
